# dsh-approve-for-me 设计

本文供修改实现、审查机制和选择验证方法时使用。产品行为、默认值和验收要求由[需求](<requirements.md>)定义；安装与设置见[用户参考](<user-reference.md>)。

本文说明机制与必要理由，不另存一份普通界面字典或测试操作清单。验证环境和操作方法见[验证说明](<verification.md>)，写作与同步规则见[文档原则](<documentation-principles.md>)。源码名称用于定位核验；运行测试和探针需要完整源码。

第 11 章列出未验证范围。实现存在、离线测试通过或文档修订，都不等于产品验收通过。

## 1. 总体架构与宿主接口

### 1.1 审批应答者与模块

插件在宿主 `approval/request` 的瀑布式流程中注册前置应答者。工具申请更宽权限时进入审批；未接管的请求调用下一个应答者。插件保留宿主沙箱。

```text
工具申请升权 → 宿主审批服务 → 接管判定与规则检查
                              ├─ 不接管 → 原宿主流程
                              ├─ 确定性拒绝 → rejected
                              └─ 独立 LLM 审查 → 结算／可选人工
```

宿主请求携带 Agent、工具名、可选工具调用标识、理由和中止信号，不直接携带参数。工具调用标识关联工具事件；宿主审批请求 id 关联申请与结果，两者不能混用。

| 职责 | 源码模块 |
| --- | --- |
| 组装与注册 | `lib/index.js` |
| 配置与模型解析 | `lib/config.js`、`lib/model-resolver.js` |
| 主会话与子代理接管 | `lib/mode.js`、`lib/subagents.js` |
| 规则、动作回查与上下文 | `lib/policy.js`、`lib/transcript.js` |
| 只读工具、提示与模型循环 | `lib/readonly-tools.js`、`lib/prompt.js`、`lib/reviewer.js`、`lib/agent-texts.js` |
| 状态机、等待与调度 | `lib/gate.js`、`lib/scheduler.js`、`lib/pending-state.js` |
| 会话模型选择与 RPC | `lib/session-store.js`、`lib/session-model.js`、`lib/bridge.js` |
| 审计与记录 | `lib/audit.js`、`lib/trace-store.js` |
| 客户端与协议声明 | `client.js`、`typert.host.js` |

每次审查独立调用 `llm.stream`，不创建执行 Agent 子会话。审查工具只在本次模型请求中声明，由插件只读封装执行，不进入宿主工具目录和审批流程。

### 1.2 运行时契约

宿主行依赖 `approval`、`llm`、`sessions`。权限预设、配置和客户端状态服务按实际可用性读取。服务缺失按需求降级，不能假装已接管。

应答结果为 `allowed-once`、`rejected` 或 `cancelled`。只有 `allowed-once` 授权本次操作。宿主另有 `unavailable` 表示没有可用应答或异常归一化；插件自身异常路径按拒绝结算，不返回非法值。

状态机的接口包括配置快照、接管判断、动作回查、规则检查、审查、计时、中止、卡片撤回、通知和审计。每个请求独立持有状态与资源，结算后清理。模型请求不传执行会话的 `sessionId`；通知使用生产者来源 `{kind:'plugin:approve-for-me'}`。

### 1.3 宿主契约核验

兼容目标由[需求 1.3](<requirements.md#13-当前兼容基准>)定义。升级宿主需重新核对审批瀑布、沙箱升权、工具事件、配置更新、模型目录、客户端槽位和持久化校验。

客户端加载须由浏览器中的注入表、实际 DOM 和交互确认。后端 RPC 正常不能证明客户端已加载。插件不改宿主源码，也不直接修改宿主服务来绕过接口缺失。

#### 1.3.1 安装声明与依赖钉版

宿主加载检查优先读取 `package.json.engines.dsh`。该字段存在时不再读 DSH peer；缺席时才检查名为 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*` 的 peer。cordis peer 不参与此检查。版本用 `semver.satisfies` 比对，包含预发布版本。精确版本豁免不是正常安装路径。

当前 `engines.dsh` 与 `dsh-llm`、`dsh-typert-protocol` 两条 peer 都精确声明 `0.2.1-rc.2`。范围声明会放宽到未经验证的宿主，不采用。`engines.dsh` 不能使用 `workspace:` 协议。

两份宿主对接包只列在 `peerDependencies`。宿主环境提供它们；插件宿主侧模块只用其主入口。profile 内没有本地实体时，由宿主导入拦截解析到自身安装树。客户端只消费浏览器加载器提供的模块，协议入口只依赖包内声明的 `zod`。

采用 peer-only 的理由是避免插件在 profile 内重复安装宿主包。已观察到的安装风险有明确条件：pnpm 12.8.1、提升布局、`autoInstallPeers=false`、暖 store，且 profile 路径不少于 62 字符时，remove 可把本地 `dsh-llm` 清成残壳。宿主优先选本地候选，不因残壳缺文件而回退，随后冷启动会失败。peer-only 消除本插件引入该实体的路径，不修复包管理器或宿主解析器。

该策略依赖两个前提：宿主导入拦截成立；宿主安装通道不自动安装 peer 实体。当前宿主的拦截已有装卸对照依据，未完成项见第 11 章。宿主解析或安装设置变化时须重验。

cordis peer、schemastery 与 zod 的约束保留在包清单中。zod 的顶层范围和宿主对接包的精确依赖可产生不同副本，不强行去重。重锁时分别核对声明是否满足。CI 与开发接线从同版宿主锚点解析两份对接包，核对实体版本与同树来源；错误版本和混树必须失败。

## 2. 请求识别、接管与子代理处理

### 2.1 插件侧判定与跳过

先判断接管，再解析审查模型。预设优先取 `permissionPresets.current(session)`；服务不可用时折叠最近的 `permission/preset` 事件。仍未知时按 `trigger.unknown` 处理。空预设清单不匹配任何已知预设，不改变未知预设分支。

`enabled=false` 在装载期不注册应答者和覆盖监听。`mode=off` 是请求期跳过：冷启动仍注册，热切换无需重新注册。监听与应答者各注册一次，启动行如实记录注册态。工具过滤、非升权和关闭模式均不解析模型、不调用 LLM、不通知执行助手、不新增插件记录。

`getState.active` 复用接管判定原语。每次现读配置，先按 `mode` 短路，再折算预设；off 时 `active=false`，预设名仍上报。状态查询没有具体审批请求，委派覆盖分支只在审批入口生效，控件显隐沿用本会话或默认预设折算。

会话模型控件只消费 `active`，不另猜权限组合。旧结果没有该字段时照常显示。关闭模式不删除历史记录入口，也不删除已保存的会话模型选择。

升权理由按 `escalate sandbox to <mode>: <justification>` 解析。权限宽度依次为 `read-only`、`workspace-write`、`danger-full-access`。未知目标按超过任意上限处理并拒绝。

### 2.2 子代理覆盖

委派身份须同时满足：`parentSession` 是非空字符串，`delegationDepth` 为数值且不小于 1。不能只看父会话或 `isSeeded`。

| 会话形态 | 父会话 | `isSeeded` | `delegationDepth` | 处理 |
| --- | --- | --- | --- | --- |
| 主会话 | 无 | false | 0 或缺席 | 本会话预设，保留人工 |
| 用户分叉 | 有 | true | 0 或缺席 | 本会话预设，保留人工 |
| 非 seed 委派 | 有 | false | ≥1 | 按委派覆盖规则 |
| seed 式委派 | 有 | true | ≥1 | 按委派覆盖规则 |

委派的 fork 后端也通过 `childSessionMeta` 构造身份，不能当成用户分叉。`session/end-seed` 和续传不改会话头。其余不属于现存委派形态的组合按主会话处理；非数值深度按缺席处理。

分叉不追加审批策略，不沿根链判断，记录 `origin='main'`。`modeOf` 无委派覆盖结果，按本会话预设及未知预设规则处理；`fallback=ask` 的人工通道保留。

委派沿父链找根会话。父链断、根不可判定、根预设未命中或覆盖关闭时不覆盖。命中时只追加 `approval/policy {policy:'ask'}`；已为 ask 不重复写。不设置整套预设，以免改变委派沙箱。

创建监听在 `session/created` 中同步追加，先于子代理首步。事件只写宿主接受的 `policy` 字段。监听内部捕获错误并审计，不影响会话挂载。

off 期间不追加策略；热启用只影响其后新建会话。装载时的一次补扫不会因 mode 热切换重跑，因此 off 期间创建且保持 never 的委派会话，其升权仍不分发审批。停止覆盖不追加撤销事件。

被覆盖委派没有人工通道：不调用下一个人工应答者、不登记卡片；即使 `fallback=ask`，审查未允许也拒绝。通知送给发起操作的子代理。

## 3. 审查输入、只读工具、策略与输出解析

### 3.1 动作回查与独立参数

按调用标识倒序回查事件。直接调用读 `tool/call.data.callId`，参数为 JSON 字符串；代码派发读 `tool/ptc-dispatch-start` 或 `tool/code-dispatch-start` 的 `data.subCallId`，参数为对象。

同一次事件快照折算两个目录：

1. **会话当前目录**：倒序取最后一条合法 `working-directory/change.cwd`，否则取会话头 `header.cwd`。合法值须为非空绝对路径，按运行平台的 `node:path` 判断；非法事件跳过继续查。再无合法值则缺失。
2. **实际执行目录**：绝对 `workdir` 直接采用；相对值按会话当前目录 resolve；缺省、空串或非字符串按会话当前目录。相对值而无会话目录时，实际目录缺失。

`cwd` 表示实际执行目录，`sessionCwd` 表示会话当前目录。目录选择不是授权；不可信 `workdir` 仍受只读路径围栏限制。快照绑定本请求，后续目录事件不改写在途证据，也不声称覆盖审批后才发生的目录变化。

实际目录缺失记 `cwd`，会话目录缺失记 `session-cwd`。即使绝对 workdir 可确定执行目录，会话目录仍可缺失。动作回查失败，或无命令类键而按 `unknownSubject` 处理时，记 `command`；reject 直接拒绝，review 携缺证标记送审。

模型输入分为系统提示、上下文证据、待审动作。完整真实参数独立放在动作消息中，不受上下文取样条数影响。动作的目录只指实际执行目录，原始 workdir 留在参数中，不并列成两个执行目录。

执行目录缺失时，相对只读取证回退到本请求固定的插件进程目录。说明必须指出它不是本次操作目录，所得相对证据不是已核实目标位置。保留回退是为了提供可核实的取证起点，不猜宿主部署回退目录。

### 3.2 上下文取材与脱敏

一次无参 `snapshotEvents()` 取得事件数组，取最近的请求头、步骤结果、消息、工具调用与结果、两类代码派发事件。分页接口变化需随宿主升级重验。

`context.maxEntries=0` 先于读取和服务检查，直接得到空证据、零条数、未截断、无读取失败标记。本次动作仍独立送审。单条与总字节预算为零时，各自不裁剪。负值和非整数由装载 schema 拒绝。

来源标签由采集代码添加，不能由正文决定。只有下列四种授权来源；标签与分隔符在两语中逐字一致。

| 事件或来源 | 行首标签 | 分级 |
| --- | --- | --- |
| `source.kind='user'` | `user:` | 真人输入 |
| `user-question-reply` | `user (ask_user_question reply):` | 询问工具应答 |
| `agent-instructions` | `user (AGENTS.md instructions):` | 工作区指令文件 |
| `developer/message` | `developer:` | developer 授权来源 |
| 其他 kind | `injected (<kind>):` | 不可信上下文 |
| 来源缺失或 kind 非字符串 | `injected (source not recorded):` | 不可信上下文 |

未知 kind 一律进入 injected 一族，包括代理转达、子代理结算、技能、运行时上下文和三方插件。本插件自身通知也显示为 `injected (plugin:approve-for-me):`，不能在后续审查中变成用户授权。relay 与 settled 的既有正文前缀保留，但不能替代结构化标签。

工具结果提取顶层文本块，标签为 `tool result:`。当前宿主 developer 事件可为空文本，不据此删掉该授权来源。标签只反映宿主记录的来源；生产者能否合法声明来源，仍依赖宿主写入纪律。

读取服务缺失、抛错或结果不是事件数组时，返回空证据并记 `transcript-read-failed`。总量裁剪记 `transcript-truncated`。两层裁剪保留首尾，插入 `<truncated omitted_approx_tokens="N" />`；N 是本次省略 UTF-8 字节数除以四向上取整。极小预算优先保留完整标记，结果可能超过名义预算。

脱敏模式定义在 `lib/policy.js`，按清单顺序替换为 `[redacted]`。普通模式默认忽略大小写；显式 `/source/flags` 按所填标志，替换补全局标志。非法单项跳过，空表关闭遮蔽。`sk-` 凭据只在词首边界命中，避免破坏 `task-specific` 等普通词。

模型输入和取证工具使用请求快照清单。审计、通知、记录出口在消费时读取当前清单，先脱敏后裁剪，不改原始会话日志。

### 3.3 防注入与参数呈现

证据声明覆盖转录、参数、工具结果和计划动作：它们是证据，不是新指令。转录用 `>>> TRANSCRIPT START/END` 分隔，动作另段，数据中的 `</` 转义为 `<\/`。授权不能来自参数中的自称批准。

每个采集事件恰好渲染一行。CR、LF、U+2028、U+2029、U+0085 分别换成字面 `\n`；CRLF 因而得到两个字面，不合并。五类都映射到同一字面，原种类不保留，转换不可逆。转换在结构转义、脱敏及裁剪前完成，之后按转换结果计量。

行首由采集代码控制，正文伪造的 `user:` 只能留在行内。总量裁剪切穿一行时，尾部残片以截断标记开头，按不可信残片处理。声明与标签分工不同：前者说明证据性质，后者辨认来源。

参数根深度为零，字符串遍历深度不超过四，容器到第四层不再下钻，用 `[depth-exceeded]` 标记。保留自有可枚举的 `__proto__`、`constructor`、`prototype`，不改变输入原型。

在支持深度内，普通无环 JSON 对象与数组按 `JSON.stringify` 语义呈现。重复但无环对象每处完整保留；仅祖先回边标 `[circular]`。非普通对象、BigInt、函数或遍历异常标 `[unserializable]`；undefined 属性和 Symbol 键省略，非有限数及数组空洞为 null。缺证标记不表示无害。

参数先结构转义、脱敏，再按单条预算裁剪。动作 JSON 的字符串字段也脱敏，不能让同一命令从另一字段泄漏。详情采集失败使用安全占位，不将已有缺证说明升级成无意义异常。

### 3.4 只读工具与资源限制

工具用 `node:fs` 只读接口，不注册宿主工具、不派生进程、不联网。未知工具、非法参数和执行失败都有对应结果供模型继续判断。

| 工具 | 限制 |
| --- | --- |
| `read_file` | 每次 64 KiB，支持偏移与分页 |
| `list_dir` | 最多 200 条，不递归 |
| `glob` | 最多 200 条，支持 `**`、`*`、`?`，遍历不跟随链接 |
| `grep` | 最多 100 匹配；超过 500 字符的行整行跳过；每文件 1 MiB、候选 200、模式 256 字符 |
| 遍历 | 最多 4000 个目录，达到预算须说明搜索不完整 |

路径拒止规则覆盖 UNC、设备命名空间及凭据名称：`.credentials*`、`.env*`、`id_rsa*`、`id_ed25519*`、`*_history`、`.netrc`、`.git-credentials`、`.npmrc`、`settings.yaml/yml`、`.pem/.key/.pfx/.kdbx`、`.ssh`、`.aws/credentials`、`.docker/config.json`。字面与真实路径都受限制。

DSH home 围栏同时比较目标与根的字面、真实路径。环境根与仍存在的默认 `~/.dsh` 根都受限；不存在时按字面比较。范围包括会话、认证信息与插件记录，工作区普通同名目录不因此被禁。目录列表可显示凭据名称，不读正文。改名副本和硬链接另有识别限制，不能用该限制解释敏感字面路径漏检。

grep 跳过超大文件和超长行后继续，并报告跳过数。候选数达到上限停止收集并说明。目录预算同样须说明。

模型派生的正则不在主线程执行。grep 在主线程完成参数、静态模式、编译、敏感路径与候选检查；工作者线程完成文件检查、读取和逐行匹配。glob 在主线程遍历，把相对路径按目录批次交工作者匹配。

每次工具调用创建工作者，收尾终止。超时或取消通过 `terminate()` 强制结束同步回溯，主事件循环仍能响应。创建失败或异常退出返回工具错误，不直接改变安全判断。

静态模式检查先拒止已知病态类：嵌套量词、歧义选择、反向引用，以及连续四个以上相邻带量词原子。静态检查不是通用时限证明；剩余表达式靠可终止工作者约束。

目录、语言、工具时限和脱敏清单在调度前拷贝并绑定请求。单工具时限零立即超时。四工具结果作为独立 tool 消息回喂，不并入转录标签；结果内形似来源标签或分隔符的内容仍是不可信证据。

### 3.5 可选拒绝规则

`denyPatterns` 是用户自选文本规则，默认与参考清单分开。筛选顺序固定：关闭、工具过滤、非升权先跳过；升权上限检查；内置危险拦截；用户规则编译与扫描；最后处理 `unknownSubject`。全部确定性检查先于模型解析和调用。

用户规则扫描支持深度内的全部自有字符串值，不扫描键名。键路径只用于指出位置，例如 `env.PAYLOAD`、`args[0]`。回查失败没有值可扫；无命令类键但其他字段有值时仍扫描。

| 无法辨认动作时 | 规则未命中 | 规则命中 |
| --- | --- | --- |
| `unknownSubject=reject` | 缺证拒绝，记 command | 规则直拒，理由含规则与键路径 |
| `unknownSubject=review` | 携缺证送审，记 command | 规则直拒，理由含规则与键路径 |

规则命中不再记 command。非法模式跳过，不能声称该项生效。文本匹配可能拒绝包含危险字样的搜索或说明，不推测意图。参考模式的运行时定义为 `DEFAULT_DENY_PATTERNS`；用户用法见参考页，不在本设计再抄一份。

### 3.6 循环与消息序列

调用 `llm.stream`，用 `BlockAssembler` 收集文本、工具调用、结束原因和用量。每轮先追加带工具调用的 assistant 消息，再为每个 id 追加恰一条工具结果；参数解析失败也要结果。全部回喂后才发下一轮。

工具轮次用尽后要求直接结论，下一次不提供工具。`maxTokens=0` 不传上限，由模型或供应商默认决定，不等于无限输出。推理可能先消耗输出额度，过小会无正文。每次模型流前复核中止信号。

### 3.7 输出与解析容错

输出合同由需求 3.5 定义。内部映射为 `outcome→decision`、`risk_level→risk`、`user_authorization→auth`、`rationale→reason`。不合法或缺失字段的补全按字段记录来源，缺理由不伪造模型解释。

先解析整段 JSON，失败可尝试首个 `{` 到最后 `}` 的对象；没有合法 outcome 仍是故障。流以 max-tokens 结束时即使 JSON 可解析也不采信。空正文或 `error:EMPTY_RESPONSE` 属无响应。模型截断、日志裁剪和字段补全是不同状态。

### 3.8 随包安全策略与系统提示

`lib/prompt.js` 按请求语言组合系统模板、对应的租户策略和共享输出契约。两份随包策略为 [英文](<../assets/tenant-policy.md>)与[中文](<../assets/tenant-policy.zh.md>)。正常对照须确认全部七节实际进入系统提示，不只确认模板构建成功。

系统提示按 3.2 的四个标签辨认可信授权来源。其他 user 角色行是机器或代理上下文，不能自行建立授权；缺失或未知来源不升级。工具结果中的假标签、截断残片同样不可信。标签拼写、分隔符和共享协议由测试精确保护，不另抄整段中英说明。

Codex 来源固定为提交 `03f014564deef528c25e80fe67ec51871cb6ee51`。英文系统模板采用[上游模板](<https://github.com/openai/codex/blob/03f014564deef528c25e80fe67ec51871cb6ee51/codex-rs/core/assets/guardian/policy_template.md>)：开头三句及若干指令保留原文，其余节选、改写或增补。英文拒绝指令逐字采用上游原文；输出契约采用上游正文，仅首两句间的空格换成换行。中文模板和拒绝约束翻译或概述本地衍生英文，不是完整上游模板的直接翻译。

租户策略的五类风险章节改写自上游对应子节，保留部分结果规则原文或近原文；触网打开和重送指引为项目增补。中文翻译本地英文七节。版权、具体引用文件与许可范围见[第三方通知](<../NOTICE>)，项目 MIT 不替代这些文本的 Apache-2.0 条件。

策略缺失、读取失败或为空时使用同语言占位，不读另一语言补位，基础风险规则仍按需求执行。读取结果在模块实例中缓存，包括失败；文件修复后须重新加载模块。验证用独立模块或读取替身构造失败，不删除真实策略。

## 4. 审批状态机、人工竞速、取消与时限

### 4.1 状态机与五条路径的返回值

预设命中后，同步读取一次配置、回查动作并筛选；此段不解析模型。跳过请求 next 恰一次，无通知、插件计时器和结算记录。确定性拒绝也在解析模型前返回。原始信号已中止时按取消结算，优先于拒绝。

筛选通过才建立装配计时器和取消监听。模型解析、证据采集、排队、审查、人工、取消和时限进入同一竞速，共用最终状态守卫。

```text
筛选 → 跳过／直接拒绝／审查
审查 → allow → allowed-once
     → 未允许 → 默认拒绝／主会话可选人工
     → 人工先答 → 人工结果
     → 取消或人工通道关闭 → cancelled
时限或异常 → 对应拒绝／取消，清理资源
```

`next()` 至多一次。审查中卡片开关打开时启动人工等待；关闭时仅确实交人工才调用。委派无人工、规则直拒和内部异常不调用人工备用。内部异常统一拒绝，通知归通道故障，不写成危险判定。

入口逃逸与状态机最外层捕获须自身防抛。配置不可读时使用 schema 默认的语言、脱敏、通知、审计与记录计划；预设取不到就缺失，不伪造。筛选与后续模型解析共用本请求快照，热改只影响下一请求。

### 4.2 撤回机制

原始 signal 只表示工具取消。下传前创建独立卡片撤回控制器，合并为下游 `req.signal`；审查和取消监听仍使用原始信号，不能把自身撤卡误当工具取消。

只撤回实际显示过的卡片。冻结请求或网关不可用记 `withdraw=unavailable`。人工先答、取消会中止模型流；迟到结果只留观测，不再结算或通知。

收尾清计时器、监听和卡片状态，并恢复原始 signal。恢复仅在请求字段仍为本次投影时执行，不覆盖后续改值；恢复失败只留观测，继续其余清理。冻结对象没有投影写入，也无需恢复。

宿主同一请求对象的再次派发发生在收尾之后，按新审批处理。不为没有已知宿主路径的“同对象未收尾并发再派发”增加跨请求登记。计时回调抛错按当前环节拒绝，中止回调抛错按取消。两类故障通常以 source=error 留痕；装配计时回调抛错按装配超时归 source=timeout，计数见 5.3。

### 4.3 时限与人工等待

审查预算覆盖配置读取、动作回查、模型解析、证据采集与等待结论。同步筛选消耗也计入。进入竞速时，装配计时器取本请求预算减去从请求进入起已经流逝的时间；不另加固定装配上限。

模型解析与证据采集各步同装配计时器竞速。到点不再等并弃置迟到结果；宿主服务没有中止签名时不能物理停止该步骤。结果按装配超时拒绝并计数，不写成模型审查超时。

排队独立计时，不消耗审查预算。进入调度前先检查已耗时，取得许可后的开始回调再复核非排队消耗：`elapsedExQueue = max(0, Date.now() - max(0, queueMs ?? 0) - requestEntryAt)`，剩余值为本请求审查时限减去该消耗。装配与调度交接开销计入，不扣排队，不赠送新时限。计时器此前用不结算的占位竞速者；剩余为正才武装并补卡片截止时间，模型超时先中止流再拒绝。

进入调度前已知审查预算为零或装配耗尽时，不开始尝试，也不弹卡。此路径结算与信号恢复在同一同步块，宿主未必观察到即弹即撤，可能遗留可操作卡片，因此检查先于弹卡。

许可回调复核发现剩余非正时，走独立的 `assembly-exhausted` 分支：中止审查信号，不开始模型尝试，按 rejected/timeout、stage=assembly 结算，不钳成短暂审查超时。此时可能已显示审查中卡片，须按正常撤回路径收尾。已启动任务的终态负责计数，gate 不重复计数。

人工起算为 request 时，从审批入口计时，装配、排队和审查均消耗人工预算；handoff 则在确实交人工时计时。零或剩余耗尽立即拒绝，不登记无截止人工状态。

审查中卡片已由用户开启时，人工预算耗尽可在异步竞速中立即结算并撤回。它与审查零预算不同：已有异步边界，撤回可被宿主观察。卡片尚未出现而人工预算已尽时，不为交人工再造闪退卡片。

### 4.4 注入范围与上下文影响

通知区分允许、安全拒绝、规则命中、装配／排队／审查／人工超时和通道故障。规则命中模板解释形态、位置及合规重送，不带禁止绕过末句；该末句用于模型安全拒绝、升权超上限和人工拒绝。无证据直拒仍用安全拒绝模板。

规则重送须按改写后动作独立判断；仅换等价写法达到相同危险结果仍是绕过。超时取真实环节和实际生效时限，尤其排队时限取调度失败包络，不在结算时现读。冷却提示稍后重试，不能鼓励连续请求。

逃逸与内部异常复用通道故障模板，带真实原因，不另存专用正文。通知先按出口生效清单脱敏，再按字节预算保头和完整标记；零不裁剪，极小预算可被标记超过。通知失败记降级，不改结果。

## 5. 调度、有限重试与持续故障控制

### 5.1 调度

每个接管请求独立排队、独立审查，不合并在飞任务、不复用结论。同一 `(sessionId, callId)` 或同一请求对象再次到达，也必须重新判断本次证据与授权。

全局并发、同会话串行、全局队列共同限制启动。超容量为 `queue-overflow`，超等待为 `queue-timeout`。`queueMs` 由调度器测量到取得许可；立即许可为真实零。入队前冷却、队列已满没有等待期，该值缺失；排队超时或交接冷却携实际等待。

开始回调由真正发起审查的一方在许可交接复核后、模型调用前触发，传入实际 queueMs。gate 按 4.3 重新扣除非排队消耗，剩余非正就按装配耗尽中止，不开始尝试；为正才启动计时器。未开始任务的失败路径不武装审查计时器。直连测试也须履行此接口，不能靠 gate 预测。

取消信号已中止时不入队；排队中取消即时移除并释放容量；取得许可到启动之间再复核，已取消就释放许可。唤醒和启动前也复核当前调度器冷却，冷却命中不执行、不计数；交接拒绝携实际等待，不自动重新排队。

排队取消或超时先到就按该结果，不被冷却改判。人工先答等使排队结果迟到时，仅留观测，不重复结算。任务在每轮模型流、工具步进与重试前复核信号，避免无效调用。

`concurrency.*` 与 `breaker.*` 在装配调度器时定格。普通配置变更重建实例并清空新实例计数，在飞和排队请求仍按旧实例值完成。排队失败包络携实际等待上限，通知不被后来热改改写。

队列等待零值表示需要排队即到点；冷却时长零在下一次检查结束并清计数。并发零没有可启动审查，队列容量零只允许可立即运行的请求。这些不是无限等待。长期登记和写队列均须有清理或容量上限。

### 5.2 有限重试

每次审查最多两次尝试，共用装配后的剩余时限。可重试供应商错误和空响应，包括可间歇恢复的 `INVALID_REQUEST`、`EMPTY_RESPONSE`。截断、模型解析失败、装配错误不重试。

重试从相同系统和动作输入重建完整消息序列，不沿用半轮工具消息。工具观测跨尝试累计，理由保留固定进度前缀 `attempt N/M: `。一次审批只形成一份审查记录和尝试摘要。信号已中止或零预算时不启动尝试。

### 5.3 冷却计数

一次审查任务只计一次终态，内部尝试不分别计数。deny 与 error 都参与持续不可信结论计数；记录仍区分风险拒绝和故障。

队列满、排队超时、冷却未执行、排队中止未执行任务，不计。人工抢答、取消、关闭和人工时限先结算造成的被替代审查不计。装配与审查超时计审查错误；两环节计时回调抛错同权，人工时限回调抛错不计。

计数入口按任务是否开始分开：进入调度前的装配超时由 gate 调用 countTimeout；许可回调的 assembly-exhausted 已进入任务体，经审查中止结果由任务调用 scheduler.record，gate 不再补计。同一请求只计一次。

计时回调异常的最终 reason 仍是故障本身；装配环节 `source=timeout`，审查与人工环节为 error，stage 取真实环节。冷却期间不调用模型，到期清计数恢复。allow 清连续计数，deny/error 使其增加；窗口保存最近结果，任一阈值达到即开启冷却。阈值零不关闭保护，甚至 allow 后的零计数也可能满足零阈值；windowSize 零在每次记录后清空窗口，仍不改连续计数。

## 6. 模型选择、配置读取与请求快照

### 6.1 配置结构与更新

设置命名空间为 `approve-for-me`。批准默认和合法范围见需求第 5 章；用户表可完整呈现并逐字段核对。`.volatile()` 是宿主热更新资格，不表示页面为所有字段提供控件。

热更新集合包括 mode、工具、升权上限、规则、缺证与备用、trigger、reviewer、human、通知、审查中卡片、trace 显示与采集档、语言。enabled、调度、冷却、审计、上下文、记录体积等普通字段沿宿主生命周期更新。

`normalizeConfig` 按分节合并，单独处理 `ui.trace` 两层和 language，解包稳定 volatile 引用。面向客户端的 schema 不含函数转换节点，避免多次序列化丢失回调而使表单空白。

装载 schema 拒绝非法值；volatile 写入可原地改变引用，读取层再核温度、非负安全整数预算和五个毫秒字段。毫秒同集包括 reviewer 两项、human 时限、队列时限、冷却时长，范围为 0–2147483647 整数。其余非 volatile 数值走装载校验。

温度为 `[0,2]` 有限数。schema 边界附 `Number.MIN_VALUE` 退化步长：所有有限双精度数都是该值的整数倍，不损失合法连续值；NaN 的取模结果不能通过整除检查。该纯数值元数据可跨序列化，不用回调或全局类型解析器。读取层再次拒非有限和越界值，不静默钳制。

每请求配置快照绑定目录、语言、工具时限、脱敏、采集档和详情预算。排队中变化不改在途计划。出口脱敏是需求规定的消费时点例外，采集档不属此例外。

### 6.2 模型选择对象化与解析顺序

选择值兼容字符串和 `{model, effort}`。目标引用按首个斜杠切 provider，模型 id 其余斜杠保留。映射条件与目标路由分开：`parent.provider` 空值表示任意，`parent.model` 始终是完整纯 id，`choice` 承载目标与推理强度。

条件去首尾空白，provider 空值归一为 null。同条件只允许一条规则，重复是可见错误，不按行序选赢家。装载、volatile 读取与设置页保存分别检查同一比较；运行时遇到重复也拒绝。规则只保存一份，可建精确和通用内存索引。

三层序为会话选择 → 父模型映射 → 全局默认。候选须通过 provider 可用和模型信息校验；失败直接退全局，不再试其余层，精确映射失败也不试通用。全局空值用执行助手当前模型独立调用，记 follow-parent；已设但不可用，或全局空值且实际审批取不到父路由，记 unavailable，不选任意模型。

父模型取最近 model/selection，缺席再取请求头。强度显式指定但模型不支持时不传，保留降级；未指定时支持 low 就用 low，否则不指定。界面区分所选原值和实际生效值，见 7.3.1。

映射层查找链固定：新精确 → 新通用 → 旧字典纯模型 id → 旧全引用键去首斜杠后的纯 id。旧全引用键按通用匹配；多个别名归一后选择相同则正常命中，选择冲突则忽略该条件并留审计，继续全局层。不猜原意、不自动改旧配置。

客户端行状态独立保存作用范围、纯模型 id、目标模型和强度。不按 id 有无斜杠猜 provider，不按目录首项补通用规则。选择、暂存、保存均不剥模型 id 前缀。

解析查找表有界，键含配置修订、会话选择和父路由；父模型、目录、配置或会话写入使旧结果失效。它缓存路由，不缓存审批结果。实际使用相同模型时仍是独立审查调用。

### 6.3 会话级选择的文件载体

保存于 `$DSH_HOME/approve-for-me/session-models.json`；未设 home 时取 `~/.dsh`。version 为 1，entries 按会话 id 保存 `{model, effort, updatedAt}`，归一时去单层 `session-` 前缀。`model:null` 表示显式清除，不等于没有条目。

读取依次为文件条目、无条目时兼容既有会话选择事件、其余解析层。写入不新增自定义会话事件。同目录临时文件后 rename，成功立即刷新，失败保留原文件并给可见状态。

非法 JSON 按空表降级，坏条目不影响好条目。最多 200 条，按更新时间回收；一秒读取刷新窗口仅优化读文件，不延迟成功写入生效。

## 7. 客户端交互与状态更新

### 7.1 加载、挂点与接口

客户端是宿主模块加载器工厂，使用宿主 React 和 UI primitives，不支持任意相对 require。依赖注入须完整，缺服务不能静默空白却声称成功。

| 挂点 | 标识与通道 |
| --- | --- |
| 包设置 | `plugins.bundle.config`，键为包名；`configForms.get('approve-for-me')` |
| 会话模型 | `conversation.input.left`；getState、setSessionModel、modelCatalog、modelEfforts |
| 审批详情 | `conversation.approval.detail`；保留命令，pendingState |
| 记录视图 | `conversation.view`；traceRecords、traceRecord |

加上 presetCatalog 共八个 RPC。协议扩展须同步结果 schema、类型和成员描述，漏任一处可能丢投影字段。状态提供实际模型、强度、来源、预设、接管与记录开关。没有活会话不等于不能按会话 id 保存选择。

### 7.2 设置页 GUI

只有宿主服务该命名空间且页面使用本机回环地址时显示，由 `configForms.whileServed` 管生命周期。不可写时不建第二通道，宿主 profile 配置与审批继续独立工作。

20 个产品字段由运行时字段集合定义，包括接管、模型、语言、时限、模式、升权、缺证、备用、通知、工具和规则。普通说明在字典维护，名称合同由需求 6.4 定义，不在这里抄二十组中英正文。

草稿不直接写配置。保存仅在合法且有差异时可用，失败保留草稿。“已单独设置”只表示用户层有键，未保存编辑不产生该标记；暂存 unset 未保存前标记仍在。“恢复默认”在有用户键或暂存项时显示，前者保存 unset，后者可只丢草稿而不产生写入。

映射表有作用范围、执行助手模型、审查模型、强度、操作五列。范围显式选择任意或指定 provider，目录不可读可手输。重复条件跨全部行检查，禁保存；空父模型行提示但不入保存计划。换模型保留受支持强度，否则清空。

目录下拉与自定义输入由独立编辑形态标记控制。切换时保留本行和其他行草稿，不写配置，不参与差异比较。返回列表保留缺目录原值；焦点随控件切换。纯 id 旧键首次编辑转新结构，属于真实改动；含斜杠旧键确认前只读，不参与形态切换。

旧键确认可选择“整键为任意 provider 的 id”或“首段为 provider、余段为 id”。未编辑旧键继续留旧字典；已确认或编辑的才迁入新结构并删旧键。旧字典只减不增。映射无差异不写路径；clear 后再编辑以最终列表 set，仍是显式用户覆盖。

保存成功、字段 clear 或行删除重建行状态，编辑形态标记随之重置，不能漂移到其他行。provider 目录不可读时只显示文本框；模型列仍可有当前值保留项和自定义入口。

列内控件用 border-box 统一文本框与下拉的计宽方式，避免 100% 宽叠加内边距越列。返回按钮自然换行且不越本列，不靠裁切遮住重叠。普通输入高度 34px、圆角 8px，行网格列间距 8px，实际矩形至少留 7px（1px 容差）；非网格的默认模型两下拉仍为 6px。视口不大于 520px 时收单列，较宽视口中的窄容器仍为压缩五列。两种形态都不重叠、不新增横向滚动。

毫秒读数独立于官方输入的校验提示，非法草稿不能把生效秒数一起遮掉。读数不写回配置。

#### 7.2.0 审查模型的分置醒目提示

不可用和空默认按层级显示：全局在设置页首字段前，规则在对应行附近，会话在模型控件附近。级联失败时各层提示保留，不因退全局而删规则提示。提示只解释现状，不改解析。

`modelIssues` 条目含 scope、ruleProvider、ruleModel、configured、reason、effectiveLayer、effectiveModel。所配原文只在 configured；实际模型归一为完整路由，与触发器同源。global、rule 不依赖活会话；session 仅供会话控件。

规则或会话目标不可用直接推演全局终点。无会话求值时空全局可记 follow-parent 与空引用，不能编造具体模型。实际审批取不到父路由仍按 6.2 的 unavailable 处理；诊断无会话求值与真实审批不能混为一谈。

全局空值条目用于说明“落到该层才跟随”，不是故障。会话控件仅在未单独选择时显示该提示：真正跟随用 followParent，被有效映射挡住或父引用不可用用 globalUnsetShadowed，不虚称当前跟随。已选会话模型失败时只显示会话失败提示，包含其回退结果，至多一条。

实际引用为空就省去实际模型句，以有效层说明承接；首句已表达层含义时不再重复。会话失败须带 `{configured}`，并携 `{reason}` 与可取得的 `{effective}`，因为旁边未显示原值；global 和 rule 控件已显示所配值，不重复。空引用时的 `{layer}` 来自有效层，不从原因猜测。规则目标空串可保存但按不可用诊断，旧字典空值不参与匹配。

诊断计算失败留 stderr，不编原因；配置快照读取失败时状态整体不可用，不向 RPC 抛错。警告行用宿主图标与背景，浅色文字采用更深琥珀色以满足对比度，深色用 warn-label。空默认状态同规格显示，但不说成故障。

#### 7.2.1 常驻文字说明入口（requirements §6.5）

七类字段共用字段外壳：标签、文字说明按钮、覆盖组、控件、常驻短句、展开说明。按钮有可见文字，不只是小图标。开合只改本地状态，不改草稿、保存或常驻提醒。

按钮的 aria-expanded 表示开合，aria-controls 关联说明区，名称含字段名与当前动作；说明区有 region 语义。控件 aria-describedby 关联常驻和已展开说明。点击区域至少 24×24 CSS 像素，浅深文字对比度至少 4.5:1，有可见焦点。

Enter 和 Space 由同一开合处理器处理并阻止默认合成 click，避免双触发。数字字段仍用官方 SettingsValueField 承载输入和校验，标签、帮助与覆盖组由外壳提供，不能同时出现两套按钮。

数字承载通过 `.dsafm_numhost` 收起官方空标签行并归零重复内边距。结构假设是官方根为直接子元素、首个子 div 是标签行。宿主改结构、出现空行或双按钮、数字间距与其他字段失配时，须重估承载，不用哈希类名强行隐藏。

#### 7.2.2 设置页名称与说明

稳定名称以需求 6.4 为合同，实际中英正文只在 `client.js` 字典维护。普通说明须保留空预设不接管已知预设、独立未知分支、模型独立调用、零值、预算风险、规则与内置拦截区别，以及通知与记录不同等事实，不要求逐字等于设计。

常驻说明承担不展开也必须知道的风险，帮助补充操作与条件。token 单位与过小输出额度可能无有效结论的风险不能只藏在帮助中。两条中文输出额度说明用 U+2060 防止风险词逐字拆行；事实比较可忽略连接符，显示保护须独立检查，不能随去全文冻结一起删除。

预设目录缺失保留已选 id 并给核实与重试路径，不把读不到目录当空配置。名称、占位符和显示条件依内容职责测试，不按键前缀或句长冻结。

### 7.3 会话级下拉与更新

菜单提供跟随全局、模型和强度。按会话 id 保存；未激活会话可先设，激活后使用。RPC 不可用、无 id 或写失败给可见状态，不假报成功。

权限投影触发重取 getState，另有十秒备用刷新。显隐只看 active，off 隐藏，热启用随刷新恢复。id 不翻译。会话选择不可用时显示所配引用、原因与真实回退；空全局状态按 7.2.0 分支显示。

#### 7.3.1 会话控件的含义与来源

触发器说明选择只影响本会话、审查独立调用。清除会话选择是跟随全局，不等于指定执行助手模型。菜单和触发器使用同一稳定名称及原始 id。

会话层实际生效时，强度显示所选原值，未指定显示自动选择。其他层显示解析后的有效强度；支持 low 时可为 low，否则为空并显示自动选择。显式但不支持的所选强度仍可显示原值，调用不传并记录降级。

#### 7.3.2 触发器结构与省略策略（requirements §5.4、§6.2、§6.4）

按钮分模型段、强度段，回退时追加标识。模型恒取 effective；强度按 7.3.1 来源取值。字段 undefined 时不补另一来源；没有有效模型时只显示跟随全局，不造强度。

模型段可收缩省略，强度和回退标识不省略、不裁切。完整当前值在 aria-label 前部，后接对应说明；可见文字是无障碍名的一部分。title 只含说明，不重复当前值。失败徽标直接可见。

触发器宽度取容器与 `100vw - 156px` 的较小值。156px 是左邻接宽与右留白预算，宿主布局变化时重验。带提示包裹层下，宿主锚点也须随包裹层收缩；不把插件外的锚点当可控对象。

提示在小于 1280px 的视口增加 78px 左边距，避开前置宿主控件；1280px 不加。只改插件几何，不提高层级、不改宿主尺寸。提示按 anywhere 换行，模型和错误长记号允许断开；不能靠不缺字认定实用可读。

1280 和 375px 的目标是强度完整、模型按剩余宽度省略、无障碍名保全。250px 下视口预算只剩 94px，模型可让到零宽。固定开销约 38px，再加强度段；英文自动选择最小宽可超过预算，回退标识还增加开销。此时内容可越按钮盒，按钮盒自身仍不得越容器和视口，不能宣称全部内容都在盒内。

极窄提示保持当前布局但有实用可读性缺口：78px 避让加上约 50px 最小盒宽，可形成逐字竖列或少量横向越界。去避让会遮住文字，单改左距无法同时满足文本区不遮挡和包裹层右缘。可复制的 DOM、无障碍名与菜单提供另一读取路径，不代表视觉问题解决。

现有中文边界为不大于 300px 的局限形态、320px 起有端点可读依据；英文不大于 320px 为局限、375px 起有端点依据。251–319px 未逐帧验证，中间宽度、深色和系统缩放仍见第 11 章。中文约三字宽的文本区只是现有几何参考，不是通用英文可读标准。

### 7.4 审批卡片内的自动审批状态条与倒计时

pendingState 的状态为 reviewing 和 waiting-human，非法状态归 reviewing。人工阶段 cause 为 deny、timeout、error，非法或缺席归 error。reason 与记录同源，但出口裁剪可不同。cause 是 RPC 结果字段，须按 7.1 三处声明。

审查中尚在排队不显示审查倒计时；开始回调提供截止后才显示。人工阶段显示待决定及自动审查原因，不能冠最终拒绝。倒计时按状态锚定 review 或 human，deadlineKind 缺失或矛盾不能串用时限。

deny 保留模型理由；空理由省去悬空标点。timeout 表示未获有效结论，error 按显示类别解释故障，不能写成模型判危险。人工零值不登记无截止等待。

每秒查询状态、本地每 250ms 刷新文字。结算后条目移除；宿主撤走审批块时插件一并卸载，结果由对话与记录承接。服务失败不伪造状态，保留关联命令与宿主按钮。

#### 7.4.1 卡片与记录的显示类别（requirements §6.3、§6.4）

分类只读已存在字段，不写回判定、reason、degraded 或通知。先剥一次 `attempt N/M: `，再剥一次固定 `审查未执行：` 前缀，然后按开头标记分类。

| 原始标记 | 显示类别键 |
| --- | --- |
| model unavailable | `cardcause.modelUnavailable` |
| queue-overflow、queue-timeout、breaker-open | 对应 `degraded.*` |
| empty payload、output truncated | `degraded.output-empty`、`degraded.output-truncated` |
| not valid JSON、invalid outcome: | `cardcause.outputInvalid`，保留整段原值 |
| review timeout | `cardcause.timeout`，用于记录理由 |
| 未知通道故障 | `cardcause.other`，附原值，不编造解释 |

类别与原值分开，`{v}` 为空就省去整个括号单元。卡片 deny 的 `{reason}` 不剥前缀、不归类模型数据；协议缺理由回落值只在显示时换成本语言解释。卡片 timeout 不带原值；error 的 `{reason}` 取类别单元，不直接填入判定原文。

记录先排除再归类：superseded、deny 理由、rule/hard/human 来源、装配超时及装配回调异常均保留原文。其余匹配类别；未匹配但 decision=error、source=error 或有未执行前缀时用其他通道故障，其余原样显示。truncated 是整条标记，不能据它推断理由是否被裁。

稳定原因标记是分类输入合同，修改生产者时须核消费映射。字典只维护显示正文，记录仍保留原值。degraded 的 all 与原因 model unavailable 是不同观察，不互相替代。

### 7.5 字典与语言

界面语言取宿主或强制中英，模型语言取请求快照。两语键集一致，含 `{n}` 条数、`{v}` 原值及模型诊断等占位符也须成对，名称和必要次数独立检查。未知语言或缺键应可观察，不静默换另一语言。普通字典值不在设计和测试各抄一份。

输出契约、不可信声明、缺证标记、来源标签和转录分隔符是不变块，不进入翻译字典。审计固定格式不随语言变化。模型返回文本、路径、引用和 id 不伪译。

页签标签由宿主槽位 label thunk 投影。宿主只订阅槽集合、locale 和开发工具变化，插件强制语言保存并不自动触发。保存成功且标签文本变化时，用同 id 重新注册槽触发投影；无关字段不重注册，保存失败不改正文和页签，auto 仍随宿主 locale。

拼接标点随本地化片段选择中英：模型段、错误、菜单强度、保存失败、枚举后缀、预设清单、降级多值、详情元信息、无障碍名及层说明句。宿主原始名称不是可靠语言来源，需取相邻字典片段。英文用半角与自然空格，中文用全角；枚举原值不变。扫描与渲染测试分开，不能只看字典就漏掉拼接硬编码。

## 8. 审计、记录存储、脱敏与容量

### 8.1 单行格式与关联

stderr 一行是一条阶段记录，不是一次审批的全部。阶段包括 screen、review、tool、handoff、decide、error；全文开关另启 prompt、raw。规则可在 screen 结束，异常可在 error 结束，不能只凭 decide 判断完整性。

身份、工具、目录、模型、强度、层级、风险授权、耗时、尝试、降级、通知与撤回均用稳定字段关联。格式版本常量同时供启动与阶段行。引号、反斜杠和换行转义，理由不能变多行。

reason 先脱敏再按 200 字符裁剪；整行超预算先去理由，再压缩身份等信息，仍超则截取。预算零写空行，极小值不能保全身份，结构化摘要承担复盘，不假称日志完整。

跳过降噪按会话与原因有界登记，逐次开关绕过降噪。审计写失败不改审批，启动行不含凭据。

### 8.2 摘要与可选全文

summary 提供理由、风险授权、操作与取证摘要、缺失说明、配置和策略标识，不靠全文解释决定。下表是字段合同，不是界面正文抄本。

| 字段 | 含义与来源 |
| --- | --- |
| kind、reviewId、approvalId | review/settle 类别、存储主键、两类记录合并键 |
| callId、toolName、origin、escalation、preset | 调用、发起归属、权限目标、命中预设；委派用根预设，分叉用本会话 |
| startedAt、endedAt | 本类记录起止；结算起点为审批入口 |
| queueMs、reviewMs、humanWaitMs | 排队、审查任务、确实交人工后的互斥耗时 |
| decision | allow/deny/error，仅模型侧结论 |
| risk、auth | 风险与授权分级，取模型结果或标有来源的解析补全；审查未产出时缺失，不能由 decision 推造 |
| outcome、source、stage | 最终结果、决定来源和实际环节 |
| model、effort、layer | 实际路由、强度、session/parent-map/global/follow-parent/unavailable |
| tokens、tools、attempts | 供应商返回的推理 token、取证次数、实际尝试数；不补造用量 |
| reason、subject、evidence、probes | 理由、操作、上下文、取证摘要；先脱敏，再按单条预算保首尾 |
| fieldsDefaulted | risk/auth/reason 的补全项，原始完整时为空 |
| capture | 本条审查的 off/summary/full 快照标记，旧行与结算行缺失不补造 |
| degraded、truncated | 缺失或异常标记、任一字段被裁的整条布尔 |
| configTag、policyTag | 请求配置与实际加载策略的标识 |

降级词汇保留 command、cwd、session-cwd、transcript-read-failed、transcript-truncated、`entry:<事件类型>`、all、output-truncated、output-empty、superseded、queue-overflow、queue-timeout、breaker-open、inject-fail。模型候选失败另有 `<layer>:<reason>`，显式强度不支持记 `<layer>:effort=<值> unsupported`，旧映射冲突记 `parent-map:legacy-alias-conflict`。普通多值逗号连接，inject-fail 组合用加号；无标记为 none。旧 transcript 两义只兼容读取，新记录不再产生。

configTag 是影响审查配置子集规范化序列化的 SHA-256 前 12 位，包括模式、接管、模型预算、人工、上下文、脱敏、并发冷却和模型语言，绑定请求。policyTag 为 `<语言>:<摘要>`，摘要取实际缓存加载的策略内容 SHA-256 前 12 位，缺失为 missing，不取磁盘后来状态。

审查收束产出 review，存储白名单整形，再投影和呈现。列表含合并键与摘要，不含全文；详情按 approvalId 返回。decision/model/effort/risk/auth/reason 审查优先，outcome/source/humanWaitMs 取结算，subject 审查缺失才回落结算。补充详情同样审查优先，stage 只来自结算；单边存在就取在场方。

合并起点取两类最早在场值，终点取结算、缺失再取审查。decision 在场表示有审查，outcome 在场表示有结算，不靠猜测源字段补造另一类。

全文仅主动开启后保存 prompt、input、reasoning、output。请求采集计划随审查记录携带，落盘前剥离，不成为产品字段；无或非法计划才回存储实例当前设置。排队热改不改变旧请求 capture 与内容关系。输入先请求脱敏，落盘再按出口清单脱敏裁剪；maxBytes 零回默认预算，不是无限或零字节。

只存供应商实际返回的推理，不宣称完整内部思考。采集故障不改审查；减少采集不删除已有记录。

### 8.3 自有存储与保留

JSONL 保存于 `$DSH_HOME/approve-for-me/reviews/<sessionId>.jsonl`，内存是最近窗口。approvalId 在应答者入口、配置和接管判断前生成；不接管不落记录，但异常路径也有标识。reviewId 含会话、callId、kind 和 approvalId，同一审批同类只一条，两类不互撞。

旧行缺 kind 与 approvalId 时，用其自身 reviewId 全文作只读合成合并键，独立成行，不按字符串段数识别、不与其他行合并、不写回。

每会话串行追加，装配内单实例长存。trace 设置改变时原地重配，已加载窗口立即收缩，文件行数收缩由下次写入轮转，不重建到另一存储实例。maxRecords 零回默认窗口。

回读窗口、单文件轮转、会话文件上限是三件事。超过窗口四倍时重写最近窗口，更早历史删除；文件数超上限按修改时间、同时间按名字淘汰。新写文件和仍有在飞写入的键不在本轮淘汰。窗口外记录在轮转或文件淘汰前仍可在磁盘存在。

文件淘汰回收内存窗口、计数与会话键，写队列完成即摘除。读失败或末行撕裂带 readFailed；文件不存在是合法空。坏末行跳过、下次写前补分隔。写失败暂存内存并标未持久化，重启会丢。轮转只支持单进程写者，不靠跨进程单行原子性。

审计计时登记最多 2000，模式与覆盖观察登记最多 1000，会话模型容量见 6.3。这些是资源限制，不是审批额度或授权。

### 8.4 结算记录

接管审批每次恰一条 settle，由最终守卫控制。outcome 与返回一致：allowed-once、rejected、cancelled。

| source | 结算来源 |
| --- | --- |
| hard | 内置危险形态 |
| rule | 用户规则、升权上限、缺证直拒 |
| llm | 模型直接结算或默认故障拒绝；队列满、冷却未执行也归此 |
| human | 人工抢答或人工阶段回答 |
| timeout | 装配、排队、审查、人工到点；装配计时回调异常同归此 |
| gateway、signal | 人工通道关闭、原始请求取消 |
| error | 其余回调异常、内部异常、入口逃逸 |

stage 可为 assembly、queue、review、human，能确认才写。队列满与冷却未执行为 queue；排队超时为 timeout+queue。reason 先脱敏后按单条预算裁剪。

未执行模型时模型字段缺失；规则、内置拦截、调度拒绝和入口逃逸只有结算记录。调度未执行理由保留固定 `审查未执行：` 前缀，时限来自实际调度器包络，等待与时限分开记录。

交人工后的所有结算保存可取得的 subject。已收束审查有 reason 与 queueMs 时随结算保留，即使没有 review 行；模型不可用早退有 error 审查记录，同样保存。审查期间抢答或提前人工超时没有收束结论，不伪造 reason 或 queueMs。回调异常的 reason 是异常本身，不换成旧审查理由。

迟到审查可落带 superseded 的观测行，不产生第二 settle、不覆盖最终结果；迟到人工同样不能改判。

### 8.5 自有视图与耗时

列表按 approvalId 合并，以最终结果为主。模型与最终方向不同，或模型 error、最终 cancelled 时，另列带角色标签的模型结论；allow→allowed-once、deny→rejected 同向不重复。没有 decision 就不造模型标签。旧记录只有模型结论时以它为主并明确最终结果缺失。

保留范围说明常驻，不因空列表或读失败消失。readFailed 必须提示不完整，不能假装确认没有记录。记录跟随原会话，不进会话压缩或分叉恢复。

queueMs 是调度等待。reviewMs 从许可后提示构建开始到收束或中止，包含模型、工具和尝试，不含装配和队列。humanWaitMs 仅从确实交人工到结算；并行抢答不重复计入。

审批入口到调度前的筛选与装配不另落分段。起止有效时，审批总耗时取结算跨度，前置等待是跨度减在场三段；旧起止缺失或倒置时退在场段之和。缺段显示缺失，不填零。

工具总时长从宿主记录关联，净执行取非负差值，形成工具总计＝执行＋审批。关联失败只显示已知审批数据，前置等待不能伪装为执行。插件不改宿主原生轨迹标签、位置或跨度；近似 context 行不是原生审批集成。

#### 8.5.1 记录视图的缺失解释与枚举

详情标题区分最终结果、模型结论、决定方式和模型来源。用量只表示供应商返回的推理 token，取证次数可作为摘要缺失的反证。英文条数恰一用单数，其余用复数，数值与窗口不变。

缺段按可证实信息分派：

1. readFailed 优先，所有缺段表示无法确认。
2. 任一 prompt/input/output 在场，才可证 full 采集。无采集异常时 evidence 缺可说未取上下文；tools 明确为零而 probes 缺才可说未取证。推理缺或故障正文未产生可说模型未提供。
3. 全文均缺时，只有 decision 在场且 capture 为 summary/off，才可说未开全文。capture=full、旧标记缺失或模型未执行都不能据空段推断采集关闭。
4. input 缺、reason 缺、取证数大于零却无摘要、上下文异常、其他无法确认情形，用统一缺失说明，不能伪造原因或声称开启全文能补回旧内容。

枚举以本语言含义加原值显示。未知值保留原值并说明未知，不走缺键会抛错的强制取词通道。entry:* 按前缀识别并保留完整事件值。fieldsDefaulted 和 degraded 多值逐项映射后连接。普通解释只在字典维护，稳定枚举和协议前缀独立保护。

## 9. 随包安装、停用与卸载边界

### 9.1 包声明与权限预设

bundle patch 提供插件行与 permission 行，放在宿主基线之后，用户 profile 最后覆盖。名字或 id 不匹配须有诊断，不能假装新增成功。

保留三个标准权限档，新增 auto-approve，其 sandbox/approval 与 workspace-write 相同。宿主派生取第一个匹配组合，所以新增档放在 workspace-write 之后，避免旧会话被误判开启。声明不写 defaultPreset。

不设装卸生命周期脚本。正式装卸由宿主管理依赖、bundle 与重载。实际包须含入口、协议、安装声明、用户文档和法律材料；相对链接按实际包检查，不能只读 files 清单。没有实测不能承诺免重载。

### 9.2 用户配置残留风险

插件不解析、改写或代清用户 YAML。宿主可把完整预设表存到用户层，停用后仍残留自动审批条目；选择该残留且无插件时行为等同普通工作区修改。默认指向已不存在条目时，权限行或目录可能失效。

恢复步骤由用户参考完整提供：先换标准权限档、备份配置、只移除插件条目、失败回退。装卸验证用隔离配置副本；无宿主写入路径核字节不变，有官方设置写入时只接受预期字段变化，其他内容保全。

运行模型选择与记录默认保留，停止接管不等于删除历史。干净环境卸载成功不能替代用户设置残留验证。

### 9.3 版本字段与发布核验

版本格式和发布目标见[需求 1.4](<requirements.md#14-插件版本与发布标识>)。包、锁文件两处根版本、产物与页面须完整一致。标签去 v 后等于包版本，Release 标题按需求生成。

## 12. 增补设计

本章承接需求第 10 章的已批准增补。相同机制只保留一个现行版本；本文不为暂缓项预写已经完成的实现。

### 12.1 硬性危险拦截层（需求增补 H1、H2、H3）

该层是 `lib/policy.js` 的纯文本判定，由 screen 调用。位于升权上限后、用户规则前；跳过分支仍先返回。接管后不能配置关闭，命中不调用 LLM、不交人工。它不解释完整 shell，也不以目标不存在解除拦截。

**命令装配。** 自有参数按深度不超过四探取：command/cmd/script 字符串各为一段，同对象 args/argv 字符串按单空格拼后；三键数组按序拼；没有三键但有独立 args/argv 时直接取词序；根数组拼字符串，继续探其对象元素。args/argv 只展开一层嵌套，更深静默丢弃是装配限制。枚举异常先尝试单独探取命令键，仍失败就按无命令段处理，不因本层异常逃出应答者。

理由、说明及非命令键数组不参与本层，用户规则仍扫描全部字符串。命令文本内的引号说明不豁免，包括提交信息、回显或搜索中的危险样例；内容级猜测会给伪装载荷提供通路。没有可判定命令段则不命中，由 unknownSubject 与模型路径承接。

**拆句与包装。** 按引号外换行和分号拆句；单、双引号切换各自引号态，不解释转义，未闭合到末尾仍保留。路径引号内分号不拆。误差可使语句边界偏细或漏拆，不声称单向无漏；剩余按缺上下文保守审查。

匹配忽略大小写，token 剥首尾引号，即使不成对也剥。动词、标志、目标同口径，防止 `rm "-rf"` 的引号标志绕过。动词可在语句任意位置，标志按整句归属，管道、start、调用运算符或回显不会自动豁免。

包装识别 powershell/pwsh/cmd/bash/sh/zsh/dash/ksh，去路径后判首词。执行标志为 -Command、-c、/c、/k；POSIX shell 还认全小写且含 c、不含 o 的短簇，如 -lc。大写、非字母、含 o 的簇不猜解，因 o 可消费参数。pwsh/cmd 不采用簇语法。

剥出的内层重新按同规则拆句，再递归判定，最多三层。同文本直写与包装应同判；内层分号后无空格也可拆。超深、编码、混淆或无法提取不猜解，回模型作缺证，而非安全证据。短簇静态剥层可能多拦，经安全改写重送处理。

**H1 标志组合。** 不看目标，按需求枚举直接拒绝：

- PowerShell Remove-Item 与 rm/ri/del/erase/rd/rmdir 带 -Recurse。接受完整名和 -r/-re/-rec/-recu/-recur/-recurs 前缀；无绑定视为真，`:$true` 和无符号非零十进制绑定为真，`:$false` 与数值零为假。其他串不作开关。-f 歧义于 Filter 与 Force，不单凭它命中；Force 的识别前缀为 -fo/-for/-forc/-force。任何 shell 文本的 rm -r，包括 git rm -r，都会命中 Recurse 分支。
- POSIX rm 同时强制与递归：-rf/-fr 聚合、-r -f 拆分、--recursive/--force 长选项及混合均可。短簇只接受归一字母表 r/f/i/d/v/p，可重复且不限长；含表外字母的 -force、-filter 不按簇读。PowerShell 参数拼写另判，不能据 f/r 字母把仅 Force 误判组合。
- CMD del/erase 带 /f，rd/rmdir 同时 /s 与 /q。单字母、斜杠分隔、合并簇同判；标志归一接受 2–4 字母簇，H2 操作数跳过只认 1–3 字母簇，两层边界不同。

仅 Force 或 rm -f 不命中 H1；字面目标进模型，非字面走 H2。仅递归的长选项等不在 H1 枚举的形态仍可能进入 H2。此层文本回显多拦是明确边界，不通过真实破坏验证。

**H2 目标候选。** H1 未命中但属强制或递归形态时检查目标。仅递归族包括 POSIX rm 的 --recursive 或无强制短簇、CMD rd/rmdir 与 del/erase 的 /s；仅强制族包括 PS Force、rm -f/--force、rd/rmdir /q。del/erase /q 只是静默模式，不是此处强制形态。

目标中的 `$`、`$env:`、`%VAR%`、命令替换、反引号、波浪线为动态；CMD 还认 `!` 子串，不要求闭合。PowerShell 前导 @ 和 ( 为动态，位于路径中段不算。没有目标也按不可确定。脚本先赋字面量再引用仍动态，不做赋值追踪或只读自动变量表。

审批缺少可依赖的 shell 身份。同名 rm/del/erase/rd/rmdir 采用 POSIX 或 CMD 规则与 PowerShell 动态标记的保守并集。纯 Remove-Item/ri 按 PowerShell 参数语义；前导 @/( 在跨 shell 名称上也动态，因此普通同名文件可被多拦。族只决定消费与动态标记，不改变 H1 枚举。

PowerShell 横线参数按参数名的前缀分组，跨组歧义按下文次序处理：

| 组 | 名称 | 目标候选处理 |
| --- | --- | --- |
| 目标 | path、literalpath | 冒号或下一 token 绑定值过检 |
| 取值 | filter/include/exclude/credential；erroraction/warningaction/informationaction/errorvariable/warningvariable/informationvariable/outvariable/outbuffer/pipelinevariable | 绑定值不是目标，跳过 |
| 开关 | force/recurse/verbose/debug/whatif/confirm | 不消费下一 token；冒号真值不是目标 |
| 未知 | 其他横线 token | 只跳过自身，冒号值按候选；含动态标记的 token 本身也过检 |

跨组前缀先目标、再开关、再取值：误多计候选偏保守，消费错值会藏目标。POSIX/CMD 同名命令的横线 token 不按 PS 名称消费后随值，避免 rm -i 把真目标当 Include 值吞掉；歧义造成多拦按改写重送消化。

动态横线规则仅用于未知参数，不覆盖已识别绑定分类；例如 PS exclude 的动态绑定值仍不是目标。CMD 负号不是选项，含动态值的负号文件名必须过检；POSIX/PS 同样保守检查，字面负号名无标记仍按旗标跳过。! 只对 CMD 族生效。

恰为裸 `--` 时，H2 从选项态切操作数态，此后全部 token 整体过检，不再参数分类或冒号拆分；后续 `--` 也按位置值。--force 不切换。多目标任一动态即拒绝。该态不改变 H1 标志扫描，所以 rm -- -r 仍可命中 H1。

CMD 斜杠选项和 1–3 字母合并簇跳过，四字母以上路径按操作数；POSIX/PS 不跳过 /a 等斜杠路径。单引号内的动态字符、未知绑定、POSIX 文件名前导 @/( 均可多拦，不据此放宽授权。无标志 Remove-Item $x 不属 H2，由模型破坏性动作策略处理。

**H3 系统入口。** 任意 token 基名为 mshta（含 exe）且整句含 http/https，或 rundll32 加 url.dll,FileProtocolHandler 且含网址，直接拒绝。去路径、忽略大小写，前置 start、调用运算符不豁免。只开浏览器或 explorer、不含这些入口的文本进模型判断潜在外发。

**结算与策略。** 命中 source=hard，理由带形态、参数键路径、包装层数，不置 command；没有 review 行。screen 审计保留稳定形态短码，显示含义和原值分开。没有配置项或新增设置字段，通知与记录承担结果可见性。

模型基础删除风险只适用于未命中本层的动作。随包策略同时要求：实质更安全或仅移除命中字样的重送，按新动作风险与授权独立审查；等价写法达到同一危险结果仍是绕过。policyTag 随实际加载策略变化。
