# 用户参考

[English](<user-reference.en.md>) · [中文首页](<../README.md>)

本参考说明安装、配置和查看审批结果的方法，也说明失败处理与卸载恢复。

DeepSeek Harness（DSH）运行执行助手并加载本插件。执行助手发起沙箱升权申请后，插件调用模型独立审查操作风险和用户授权，决定能否批准本次操作。下文将 DSH 称为“宿主”，将插件处理所选申请的行为称为“接管”。

<a id="known-issues"></a>
## 适用范围与保护边界

审查只覆盖进入接管范围的升权请求；范围与例外见[第2节](<#coverage>)。完全权限下不触发审批的操作不在保护范围内。

审查模型可以只读方式核对本地文件，但不能任意读取凭据、DSH 私有数据或浏览器登录与 Cookie 数据库。读取限制按路径和名称识别，不能识别改名副本和硬链接；被读到的内容仍可能发送给模型供应商。具体限制见[只读证据与隐私](<#evidence-records>)。

### 已验证范围

在 Windows 上，同一份插件安装包已在 DSH `0.2.1-rc.1` 至 `0.2.1-rc.5` 中验证：安装加载、设置保存后重新读取、模型批准、内置危险命令拦截，以及自动审查期间取消申请。与各版本官方接口包的对接检查也已通过。

实际会话与页面检查还覆盖：

- `0.2.1-rc.3`：委派子会话接管与通知。
- `0.2.1-rc.3`、`0.2.1-rc.4`：审查记录页的进入与渲染。
- `0.2.1-rc.5`：模型允许后工具执行、授权不足拒绝、人工抢先拒绝与备用人工允许、会话模型选择；卸载后标准会话可用，重装后配置和记录可回读，模型允许后工具可执行。

审查器测试还检查了工具结果中的伪指令和不同用户授权条件。这些是特定用例的结果，不代表模型不会误判。其他平台尚未验证，使用前请向维护者确认。安装后的基本确认按[第1.4节](<#14-重载首次确认与更新>)和[第2.2节](<#22-怎样启用>)进行；源码测试与部署复验由管理员或维护者按[验证说明](<verification.md>)执行。

排查问题时不要用真实敏感文件或危险命令试验。

<a id="installation"></a>
## 1. 取得安装件、安装与更新

### 1.1 版本与环境

| 项目 | 当前条件 |
| --- | --- |
| 插件版本 | `0.2.2+dsh.0.2.1-rc` |
| DSH 兼容线 | `0.2.1-rc`；支持的版本为 `0.2.1-rc.1`、`0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5` |
| 插件 Node 声明 | `>=20` |
| 建议工具链 | Node 24；本项目开发及 CI 使用该版本 |
| 宿主安装工具 | pnpm，可先用 `corepack pnpm --version` 检查 |

Node 20 是本插件声明的最低版本；运行时还须满足 DSH 及其依赖的要求。建议使用 Node 24，需要其他平台或 Node 版本时，先向维护者确认验证情况。

版本中的 `+dsh.0.2.1-rc` 表示适配 DSH 0.2.1 RC 维护线。当前仅支持上表列出的五个 RC，新 RC 发布后须由维护者更新声明并验证。安装时核对完整版本和支持列表：普通版本比较会忽略 `+` 后的部分，不能据此自动选出适配包。包内 `engines.dsh` 与两个宿主接口包的 peer 依赖声明使用相同的精确版本列表。

取得源码或安装包时，核对完整版本和支持的 DSH 版本，并保留提交标识或安装包校验信息。维护分支会继续更新，同版本也可能包含不同文件；这些信息可帮助维护者定位问题或确认回退版本。

### 1.2 从仓库制作安装包并安装

从[GitHub 仓库](https://github.com/MC5Spear/dsh-approve-for-me)取得完整源码。本适配线使用 `adapt/dsh-0.2.1` 分支；可用 Git 克隆，也可在仓库页面选择该分支后下载 ZIP 并解压。

使用 Git、Node.js 和 npm，先在独立的部署目录中执行：

```powershell
git clone --branch adapt/dsh-0.2.1 https://github.com/MC5Spear/dsh-approve-for-me.git
cd dsh-approve-for-me
git rev-parse HEAD
$package = (npm pack --ignore-scripts --json | ConvertFrom-Json)[0]
if ($LASTEXITCODE -ne 0) { throw "npm pack failed" }
```

记录输出的提交标识，并核对源码中包声明的版本和支持的 DSH 版本。`npm pack` 无需先安装开发依赖，会在当前目录生成 `.tgz`，并把文件名存入 `$package`。下载 ZIP 时，保留下载页面对应的完整提交标识；进入解压后的源码根目录执行上面两行打包命令。该步骤只制作本地安装包，不安装插件，也不向包源发布。

**重启会中断运行任务。** 安装或更新前，等待任务结束或安全停止。已有插件时先保存 `mode=off`，将默认权限预设及活动会话切回标准档。服务部署从服务进程树之外的管理终端重启。

先从目标 DSH 的启动命令或部署管理员处确认 profile 名称。profile 是实例加载的一组具名部署配置，以下以 `web` 为例；目标使用其他 profile 时，替换命令中的 `web`，并确认该配置加载 Web 界面和所需宿主服务。保持终端位于刚才打包的源码根目录，直接安装生成的文件：

```powershell
dsh plugin --profile web add (Join-Path $PWD.Path $package.filename)
```

安装命令把插件及其直接依赖装入所选 profile；宿主接口包由对应的 DSH 安装提供。

### 1.3 直接从源码目录安装

也可跳过打包，直接使用上一节从仓库取得的完整源码目录。为部署保留独立副本，不要将正在开发的工作树链接到稳定实例；源码目录须包含包声明、宿主和客户端入口、安装声明与安全策略。

安装前先核对宿主与依赖：

1. 目标 DSH 必须是上表支持的版本，并提供满足 `~4.0.4` 的 `@deepseek-ai/cordis`。
2. `@deepseek-ai/dsh-llm` 和 `@deepseek-ai/dsh-typert-protocol` 必须来自同一份 DSH 安装，且都与目标 DSH 的 RC 版本一致。
3. 源码目录若已有 `node_modules`，先核对宿主包的解析来源，或从仓库重新克隆独立副本。发现错版或来源混杂时先修正；不确定时请部署管理员协助，不要批量删除未知依赖。

目录链接会从源码目录解析插件的直接依赖。进入上一节取得的源码根目录后执行以下命令，并按上节确认 `web` 是目标 profile；`$PWD.Path` 自动使用当前目录的绝对路径：

```powershell
npm install --omit=dev --legacy-peer-deps
if ($LASTEXITCODE -ne 0) { throw "npm install failed" }
dsh plugin --profile web add $PWD.Path
```

`--legacy-peer-deps` 用于避免 npm 自动安装宿主接口包；这些包仍由已核对的 DSH 安装提供。命令完成后按下节确认 profile 中实际加载成功。若依赖解析失败，可按上一节从干净源码制作 `.tgz` 后安装；仍失败时，通过项目 issue 提供脱敏加载错误。

### 1.4 重载、首次确认与更新

安装后按宿主的管理方式安全重启，再重新加载页面：

1. 打开“插件”→“已安装”→ `dsh-approve-for-me`，核对完整版本。
2. 确认包详情页有设置表单。
3. 确认会话权限列表有“自动审批”（`auto-approve`），但保留标准权限档。这是本插件的预设，不要与宿主 id 为 `auto` 的选项混淆。
4. 确认普通会话可用。仅安装命令成功，不能证明设置和客户端已加载。

按[第2节](<#coverage>)选择接管范围并启用后，用无害的升权请求检查审批和记录。无升权的操作不会产生审批，不能用来证明自动审批在工作。

更新时从仓库取得新的独立源码副本，记录提交并重新核对宿主兼容性。备份用户配置和需要留存的记录，再按第1.2节制作新安装包，通过同一 profile 添加并安全重载。保留上一份安装件和配置备份，出现异常先关闭接管，向维护者确认回退方案。已设 `reviewer.timeoutMs=0` 的配置会立即超时拒绝；需要等待审查时改为正值并保存。

<a id="coverage"></a>
## 2. 选择接管范围，而不是授予任意权限

启用前先阅读[适用范围与保护边界](<#known-issues>)。

### 2.1 设置范围与授权的关系

| 对象 | 决定什么 | 不能代替什么 |
| --- | --- | --- |
| 工具 | 执行哪种操作；`tools` 选择哪些工具的升权交插件处理 | 工具在名单中，不等于操作已获授权 |
| 权限预设 | 宿主的沙箱范围与审批策略组合；`trigger.presets` 选择接管哪些预设 | 选择接管预设，不等于允许全部升权 |
| 升权上限 | `allowEscalationTo` 限制可自动批准的最宽权限 | 上限以内仍要通过规则和模型审查 |
| 用户授权 | 用户允许操作的目标、写入或发送的内容，以及其他影响 | 参数、文件或工具结果不能自行扩大授权 |

“自动审批”（`auto-approve`）与“工作区内修改”（`workspace-write`）使用相同的沙箱和宿主审批策略。区别是命中接管条件后，本插件先审查升权。安装不会把“自动审批”设为默认。

只处理进入宿主审批通道的请求。完全权限下不触发审批的操作不受保护；宿主策略为 `never` 而不分发审批时，插件也看不到请求。每次允许只授权本次操作，不能凭上次允许跳过新申请。

### 2.2 怎样启用

1. 保留沙箱，备份重要数据，明确任务允许修改和外发的范围。
2. 在插件详情页配置模型、工具名单及权限上限并保存。
3. 将 `mode` 改为 `rules` 并保存。
4. 在目标会话选择“自动审批”（`auto-approve`）；先用无害、确需升权的操作确认记录。

默认只接管 `auto-approve`。其他预设继续宿主原审批流程，不一定是人工审批。`trigger.presets=[]` 不接管任何已知预设；无法识别的预设仍独立按 `trigger.unknown` 处置。`tools=[]` 则相反，表示覆盖全部工具的升权请求。

### 2.3 委派子代理与分叉会话

- 委派子代理默认按委派链根会话的权限预设判断接管，包括多层委派。根会话不命中或无法判断时，不覆盖。
- `trigger.subagents=skip` 不覆盖委派子代理。已写入子会话的审批策略不会因停止覆盖而自动撤销；之后由宿主其他应答者处理，没有应答者也不会自动允许。
- 委派子代理没有人工通道。即使设 `fallback=ask`，未获允许仍拒绝；通知送给发起操作的子代理。
- 用户分叉产生的会话按主会话处理，使用本会话预设，保留人工通道。
- 子代理页面可能仍显示“工作区内修改”，不能只凭这个名称判断插件是否接管。查看实际审批结果和记录。
- 在 `mode=off` 期间创建的委派子代理，不会在重新开启后自动补接管。需要自动审批时，重新启用接管后再创建新的委派任务。

<a id="settings"></a>
## 3. 修改、保存与恢复设置

入口是“插件”→“已安装”→本包详情页。表单直接显示在详情中。每个字段旁的“说明”可展开帮助；开合帮助不改变草稿。

写入须使用宿主本机回环地址，例如 `127.0.0.1` 或 `localhost`。远程入口只读时，改用本机管理入口，或由部署管理员编辑对应 profile 的用户配置。不要把远程页面可读当作可保存。

### 3.1 保存和单字段恢复

1. 编辑字段。此时只是草稿，运行请求仍用已生效值。
2. 检查校验提示和毫秒字段的秒数读数，再点“保存”。
3. 确认保存成功及生效值更新，再发起新的请求。

“已单独设置”表示该字段已写入用户配置，即使值与默认值相同也会显示。点击单字段“恢复默认”会移除这项单独设置，**仍需保存**；随后使用宿主其他配置提供的值，没有其他配置时才使用第5节列出的出厂默认值。保存后核对生效值。页面没有一次重置全部字段的按钮。

保存失败时草稿保留。先把需要的草稿安全复制到本地，再处理连接或校验问题并重试；不要记录凭据。离开页面会丢弃未保存草稿。无改动、存在非法值或正在保存时，保存按钮不可用。

自动审查和人工作答的毫秒字段同时显示“生效”和“草稿”的秒数。保存单位仍为毫秒。空草稿可清除用户覆盖；非法数字显示 `—`，不代表已生效值变为零。

### 3.2 配置入口与生效时机

设置命名空间为 `approve-for-me`。没有页面控件的字段，由部署管理员通过该 profile 的用户配置管理。用户配置通常为宿主数据目录中的 `profiles/<配置名>/cordis.patch.yml`。编辑前备份，避免与设置页同时写入。

下面只是配置行示例，不是替换整份文件的内容。保留已有行和其他字段，仅合入所需值：

```yaml
- id: approve-for-me
  name: dsh-approve-for-me
  config:
    mode: off
```

部分分节配置会补齐未写出的默认字段。数组和字典按各自字段解释，不因留空而一律表示无限制。

第5节逐字段标明页面入口和生效方式：

- **页面保存后。** 保存后无需重启，后续请求使用新值。
- **宿主热更新。** 配置定义允许宿主不重挂载地更新，但本包设置页没有该字段控件。通过宿主配置通道更新后，后续请求使用新值；手工改文件须按宿主方式应用。
- **宿主重载后。** 普通配置变更需宿主重载插件后生效。重载或重启前先处理活动任务。

能否在页面编辑，与修改后是否需要重载，分别在第5节列出。正在审查或排队的请求继续使用进入时的配置、目录和记录采集设置。脱敏规则除外：发送通知、写入审计或保存记录时，使用当时生效的规则。界面语言在下一次渲染时更新。

非法类型、枚举、数值或重复映射条件会产生可见错误，不能靠再次保存同一错误值修复。加载已失败、表单不可用时，在配置中改正后再安全重载。

<a id="models"></a>
## 4. 选择审查模型

### 4.1 设置默认模型与本会话模型

- **全局默认：**在“插件”→“已安装”→本包详情页，设置“默认审查模型”和推理强度，点击“保存”。
- **本会话：**打开目标会话，在输入区左侧点击审查模型下拉控件，选择模型及推理强度。选择后自动保存，不需要回插件设置页保存。选择“跟随全局（清除本会话选择）”可取消本会话的单独设置，恢复按映射或全局默认选择。
- **确认结果：**查看控件显示的模型及附近提示；发生审批后，在“审查记录”核对实际模型。切换失败会显示错误并保留原选择。

会话建立后、发送第一条消息前也可选择模型。控件在关闭接管或会话不属于接管范围时隐藏，重新启用后恢复；关闭接管不会删除已保存的选择。宿主未提供接管状态时，控件仍会显示。

#### 选择优先级与不可用时的处理

顺序为：**会话选择 → 按执行助手的模型映射 → 全局默认**。

会话选择或映射选出的目标不可用时，直接回到全局默认，不继续尝试其他映射或中间层。全局默认留空时，使用执行助手当前模型，但仍是独立于执行助手会话的一次审查调用。已设置的全局默认不可用，或跟随时无法取得可用的执行助手模型，按模型故障处理，不随意选另一个模型。

设置页顶部显示全局模型问题，映射行显示该规则的问题，会话控件显示会话选择的问题。按提示核对供应商、模型和实际回退结果。模型目录可读不等于远端服务或凭据有效；持续失败时先关闭接管、修正模型配置，不连续重试。

模型引用建议完整写成 `provider/model`。首个斜杠分隔供应商 id，模型 id 中其余斜杠保留。配置兼容纯模型 id，此时沿用执行助手的供应商；没有父供应商时用首个已注册供应商。为避免解析到意外供应商，明确填写完整引用。

推理强度与模型绑定：未指定时，支持 `low` 就选 `low`，否则让模型默认值决定。明确指定但模型不支持时，不传该参数，并记录降级。输出 token 上限过小可能先被推理消耗，导致没有有效结论；不能把某个模型的额度经验当成所有模型的保证。

### 4.2 按执行助手模型设置规则

需要让不同执行模型使用不同审查模型时，在插件设置的“按执行助手的模型选择审查模型”表中添加一行，填写作用范围、执行助手完整模型 id、审查模型和推理强度，再保存。作用范围可选任意供应商或指定供应商。

手工编辑配置时，对应 `reviewer.parentModelRules` 数组中的一项如下：

```json
{
  "parent": { "provider": null, "model": "<执行助手的完整模型id>" },
  "choice": { "model": "<provider>/<审查模型id>", "effort": "" }
}
```

占位符须替换，不能直接保存示例。`parent.provider=null` 表示任意供应商；非空字符串表示指定供应商。`parent.model` 始终是完整纯模型 id，不按斜杠切开。

匹配先看指定供应商规则，再看任意供应商规则。同一条件只能有一条；比较时去首尾空白，空供应商统一为任意供应商。重复条件会阻止保存和加载。命中规则却未设目标时，将该目标按不可用处理，直接使用全局默认模型。

### 4.3 旧字典保留与确认

`reviewer.byParentModel` 继续作为兼容输入。查找顺序是新结构精确规则、新结构通用规则、旧字典完整模型 id 键、旧全引用键去掉首个斜杠后的模型 id。

- 纯模型 id 的旧键按任意供应商匹配；未编辑时仍留在旧字典。
- 含斜杠的旧键在设置页请求确认：原意是“任意供应商下、模型 id 本身含斜杠”，还是“指定供应商与其模型 id”。目录只能帮助核对，不能证明原意。
- 未确认的旧键按兼容规则读取，原值保留，不自动改写。确认或编辑后，该行才转存到结构化规则；不会同时把同一条新规则写两份。
- 多个旧全引用键归一后指向同一模型，选择值一致时可用；不一致时忽略有冲突的别名，将该映射按未命中处理，并记录冲突。
- 映射表的单字段恢复会清除用户层的新规则和旧字典覆盖，保存后才生效。保存后核对宿主其他配置提供的规则是否符合预期。

## 5. 全部配置字段

每行列出字段类型、默认值、范围、特殊值含义、页面入口和生效方式，可按字段直接查阅。

- “非负整数”表示配置定义未另设数值上限，不代表资源无限。标有“运行限”的字段还会在读取时检查安全整数范围 `0` 至 `9007199254740991`。
- 毫秒范围为 `0` 至 `2147483647`，特殊的零值含义单列。
- “—”表示无单位或不适用。除另有说明，只有省略字段才补默认；非法值会报错。
- “页面保存后”无需重启；“宿主热更新”须通过宿主配置通道应用；“宿主重载后”须重载插件。手工编辑文件的应用方法见[第3节](<#settings>)。
- 页面“兼容行”指模型映射表里的旧配置行。

<a id="redaction-defaults"></a>
六类默认脱敏规则按下列顺序替换为 `[redacted]`。普通表达式忽略大小写；`/source/flags` 按显式标志，替换时补全局标志。无法编译的单项跳过，不等于该规则正在保护内容。

```text
(?<![A-Za-z0-9_\-])sk-[A-Za-z0-9_\-]{8,}
\bBearer\s+[A-Za-z0-9._\-]{8,}
\b(password|passwd|token|api_key|apikey|secret)\s*[=:]\s*[^\s"'`]+
-----BEGIN [A-Z ]*PRIVATE KEY-----[\s\S]*?-----END [A-Z ]*PRIVATE KEY-----
Authorization:\s*[^\r\n]+
://[^/\s:@]+:[^/\s:@]+@
```

这些模式识别部分密钥、Bearer、口令键值、私钥块、认证头和连接串凭据，可能漏掉秘密。审查输入、工具结果、通知和记录都可能含私人内容。保持适当的本地访问权限，分享前人工脱敏。上下文和参数超预算保留首尾并加缺失标记；极小正预算下，完整标记本身可能超过名义预算。

## 6. 查看结果、处理拒绝和故障

会话审批卡片保留命令和“拒绝／允许一次”按钮。自动审查时显示状态和倒计时；进入人工阶段显示“等待你决定”。这还不是最终拒绝。状态通道不可读时显示宿主原卡片，不凭空推测结果。

| 结果或原因 | 意味着什么 | 接着怎样做 |
| --- | --- | --- |
| 允许 | 本次操作获准，执行助手可以继续 | 需要确认实际执行结果时再看工具结果；批准不等于执行成功 |
| 内置拦截或文本规则命中 | 未交模型，模型和人工都不能推翻 | 查看命中位置，按下节修改说明或采用实质更安全的方案，再重新申请 |
| 超过升权上限 | 请求比配置允许的范围更宽 | 优先降低权限；确有必要时由用户核对风险后调整上限并重新申请 |
| 无法辨认操作 | 默认 `unknownSubject=reject` 直接拒绝 | 让执行助手提供可核实的真实参数、目标及工作目录，发起新申请 |
| 模型安全拒绝 | 已判断本次操作不宜允许 | 用实质更安全的方案；确需原操作时，告知风险并取得用户明确授权后重新申请，规则拦截仍有效 |
| 装配、排队或审查超时 | 时限内没有有效结论，不是危险判定 | 检查对应时限和模型状态；修正后可重新申请。可交人工且启用备用时，按卡片决定 |
| 模型或通道故障 | 未取得安全结论，可能是模型不可用、空或截断输出、队列已满、冷却等 | 按原因修正；持续失败停止连续请求并反馈，冷却时先等待 |
| 人工超时 | 人工到点未完成作答，按拒绝结束 | 确认任务是否仍需执行，必要时重新申请 |
| 人工作答或取消 | 采用人工结果，或结束本次申请 | 不等待迟到模型结果改判；需要再做操作时重新申请 |

已显示人工卡片时，你可在审批结束前抢先作答。`ui.humanCardDuringReview` 控制是否在自动审查期间显示人工审批卡片，默认开启；`fallback` 控制自动审查未允许后是否转交人工，默认 `reject`，即拒绝。规则直拒不交人工，委派子代理也没有人工路径。

一次申请只能有一个最终结果。迟到点击和模型结果不能改判；仍见旧卡片时先核对审查记录，不把它当作新授权入口。安全拒绝后不能用等价命令、间接执行或换工具达到同一危险结果。

### 6.1 内置危险命令拦截

只在插件接管的升权中生效，不能单独关闭。它检查命令文本及可提取的包装内层，不是所有参数的含义分析。

| 常见命中形态 | 怎样处理 |
| --- | --- |
| PowerShell `Remove-Item` 及别名 `rm`、`ri`、`del`、`erase`、`rd`、`rmdir` 带 `-Recurse` 或可识别缩写；POSIX `rm` 同时带递归及强制；CMD `del /f`、`erase /f`、`rd /s /q`、`rmdir /s /q` | 核对目标和备份，改用实质更安全的操作，例如移入回收位置后重新申请 |
| 带强制或递归标志的删除，目标含变量、命令替换、波浪线等运行时求值，或没有目标 | 确定真实目标，以字面路径重新申请；若仍命中上一行，还须改变操作方式 |
| `mshta` 或 `rundll32 url.dll,FileProtocolHandler` 加 http/https 地址 | 由用户核实并打开网址，或先获取本地内容、完成审查后再处理 |

`rm -r` 会按 PowerShell 的 `-Recurse` 缩写匹配，即使在 POSIX 或 `git rm -r` 中也直接拒绝。部分引号、参数缩写和命令包装同样匹配。脚本先给变量赋字面路径，再用变量删除，仍按目标不确定处理。

命令文本内的引用、搜索词、提交信息也可能误命中，例如只是在说明中写了危险形态。独立的说明字段不属于这一内置命令检查，但仍可能命中自定义文本规则。

发生误拒时，先看原因中的位置。仅去掉说明里的命中字样，或采用实质更安全的操作后重新申请，不因“曾被拒绝”就视为规避。仅换等价写法达到同一危险结果仍属规避。未命中不代表安全：混淆、编码或无法提取的包装仍须由模型按现有证据判断。

### 6.2 自定义文本拒绝规则

`denyPatterns` 每行一条正则表达式。默认 `[]`。启用后，扫描受支持深度内的全部字符串参数值，包含命令、载荷和说明；键名只用于定位，不作为值匹配。根深度为零，最多处理到第四层，容器到第四层不再下钻。

普通表达式默认忽略大小写；`/source/flags` 按给定标志，未填标志也忽略大小写。无法编译的行跳过。先用无害样本检查是否有效、是否误伤，再应用到实际任务。以下只作可选示例，须手工加入才生效：

```text
(^|[^A-Za-z0-9])(mkfs|diskpart|fdisk|parted)\b
(^|[^A-Za-z0-9])format\s+[a-z]:
```

命中后直接拒绝，不调用模型、不交人工。文本规则可能误伤说明，也可能漏掉等价操作。空表只关闭自定义层；升权上限、内置拦截和缺失操作检查仍然有效。

<a id="evidence-records"></a>
## 7. 只读证据、记录与隐私

### 7.1 模型会看到什么

审查发送本次工具、真实参数、目标、工作目录、权限和申请理由；最近上下文用于理解任务。本次参数独立于上下文取样，即使 `context.maxEntries=0` 仍会送审。缺失、截断或无法序列化的内容带标记，不应当成安全证据。

授权可来自用户、developer 消息、工作区指令文件（如 `AGENTS.md`）及用户对询问工具的回答。用户明确指定按文件执行时，授权可延伸到指定内容。工具输出、技能描述、助手转述和待审参数本身不能建立新授权。

只读工具为 `read_file`、`list_dir`、`glob`、`grep`。它们不修改文件、不联网、不发起新审批，但读取结果可送往审查模型。可按需要读取工作区外本地路径；UNC 和设备命名空间读取被拒止。

| 工具或限制 | 当前资源范围 |
| --- | --- |
| `read_file` | 每次最多 64 KiB，可分页 |
| `list_dir` | 最多 200 条，不递归 |
| `glob` | 最多 200 条，遍历不跟随链接 |
| `grep` | 最多 100 匹配；每文件最多 1 MiB；候选 200；模式 256 字符；超过 500 字符的行整行跳过 |
| 遍历 | 最多 4000 个目录；达到预算时 grep 声明搜索不完整 |
| 单工具时限 | 默认 5000 ms，失败或超时作为未取得证据返回模型 |

读取检查同时核对请求中写出的路径和解析链接后的真实路径，拒绝凭据类文件和目录、DSH 会话、认证信息及插件记录。浏览器标准存储位置也在限制内，包括 Edge、Chrome 等 `User Data` 目录和 Firefox `Profiles` 目录中的登录、Cookie 数据库。

目录列表仍可能显示敏感文件名，名称识别也无法发现改名副本和硬链接。因此，即使使用只读工具，也要评估哪些本地内容可能发送给模型供应商。`grep` 达到目录遍历上限时会说明搜索不完整，不能把空结果当作目标安全的证明。

工作目录未知时会明确标缺失。只读工具可能从插件进程目录开始解析相对路径；那不是已核实的实际执行目录。操作风险取决于实际目标，不能用这个备用起点的文件来证明目标安全。

### 7.2 在哪里看结果

打开产生审批的会话 →“审查记录”。先看“最终审批”，再看决定方式、理由和实际模型。模型结论与最终结果不同会分别标注；旧记录显示“未记录最终审批结果”时，不能把模型允许当作最终批准。

- `summary` 默认保留结果、理由、操作及上下文摘要，还有已有的取证状态摘要。操作摘要可能包含命令和参数，上下文摘要可能包含会话摘录；这些内容也可能敏感。
- `capture=full` 在摘要之外，额外采后续请求的提示词、输入、模型实际返回的推理文本和原始输出。模型可能不提供推理文本；它也不是判断正确的证明。
- `capture=off` 不采上述四项全文详情，仍保存结果、理由、操作、上下文和取证状态摘要。它不是停止内容记录的开关，也不会删除历史。减少采集不删除已保存资料。
- “未取上下文”“未调用取证工具”“模型未提供”“未开启全文采集”和“本次未记录此项”表示不同情况。开启全文不能补回已有缺失。
- 能关联工具记录时显示“工具总计 = 执行 + 审批”。审批分排队、审查和人工等待；缺失时显示“—”，不推算未知耗时。

记录和通知先脱敏后裁剪，仍可能漏掉秘密。开启全文前检查存储位置权限；分享理由、截图、日志前人工脱敏。

### 7.3 保留、备份和写入失败

插件数据目录为 `$DSH_HOME/approve-for-me/`，未设环境变量时为 `~/.dsh/approve-for-me/`。其中会话模型选择保存在 `session-models.json`，审查记录按会话存于 `reviews/<会话id>.jsonl`。卸载默认保留数据。

记录有三个不同限制：

1. `ui.trace.maxRecords` 是每会话回读窗口，默认最近 200 条存储记录。窗口外暂时不可见，不等于此时已从磁盘删除。
2. 单会话文件超过窗口四倍时重写，只保留最近一个窗口；更早记录此时从磁盘删除。一次审批可能产生审查和最终结算两类存储记录，条数不等于审批次数。
3. 会话文件最多 50 个，固定值，不是可配置字段。超限删除最旧的会话文件。会话模型选择另有固定 200 条上限，按更新时间淘汰最旧项。

长期留存须在轮转前安全备份。多个宿主实例使用不同数据目录，不能共享同一记录目录。分叉会话只显示自己产生的审批，不继承原会话记录。

“记录读取失败或不完整”不表示没发生审批。写失败可能只留内存，重启会丢失；先安全保存可见摘要和现有日志，再报告，不要先删文件。重启可回读仍在磁盘窗口内的记录，但不能恢复从未写成功或已淘汰的资料。

宿主标准错误日志（stderr）含 `[approve-for-me]` 审计行。同一次审批有多阶段行，排障时保留可关联的几行。不要把审计的截断片段当作完整原始输入。

## 8. 排障与求助

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 设置和“自动审批”都缺席 | 完整插件版本、精确宿主、插件启用状态 | 任务结束后安全重载并重新加载页面；查 `skipping profile bundle "dsh-approve-for-me"` 或其他加载错误，改用匹配版本 |
| 保存失败或页面只读 | 是否本机回环入口、字段是否合法 | 保留草稿，修正入口或字段再保存；加载配置已失败则请管理员修配置后重载 |
| 会话模型控件不见 | 是否有会话 id、是否 `mode=off`、会话是否被接管 | `mode=off` 时控件隐藏；启用后按接管范围检查，不靠放宽权限强行显示 |
| 操作直接拒绝 | 来源是规则、上限、缺参数还是模型判断 | 按第6节处置，不能仅清空文本规则来关闭内置拦截 |
| 模型不可用、空输出、截断或连续超时 | 提示的模型及回退结果、预算是否为零、是否冷却 | 关闭接管并修模型或预算；冷却先等待。仍失败时停止连续请求并反馈 |
| 搜索为空 | 是否有跳过、候选截断或取证失败 | 空结果不能证明完整无匹配或安全；核对搜索不完整说明后再判断 |
| 记录缺失 | 产生记录的会话、采集档、读取或写入错误、轮转 | 先保留证据，再反馈；不要删除记录来“修复” |
| 权限行消失或日志含 `unknown preset` | 默认预设是否指向已不存在的 `auto-approve` | 按下节恢复默认引用或还原备份，不删除整份配置 |

需要帮助时，向[项目 issue](https://github.com/MC5Spear/dsh-approve-for-me/issues) 提供：插件完整版本、源码提交或安装包校验信息、宿主及 Node 版本、平台、复现步骤、脱敏配置、相关审计行或截图。去掉凭据、私人路径、会话正文和带令牌的网址。安全问题也先脱敏，不用真实危险操作复现。

## 9. 停用、卸载与恢复

### 9.1 先停止接管并保留恢复资料

1. 将 `mode` 设为 `off` 并保存，停止接管新申请。已在审查或排队的申请可能按原快照继续；确认任务已结束或安全停止。
2. 备份宿主数据目录中的 `profiles/<配置名>/` 用户配置；需要留存的插件记录也先备份。
3. 把宿主默认权限预设和需要继续使用的会话切回标准档，通常是“工作区内修改”。这一步必须先于删除预设条目。
4. 仅停用时，使用宿主插件管理的停用入口；卸载时执行下面命令。其他 profile 替换 `web`。

```powershell
dsh plugin --profile web remove dsh-approve-for-me
```

按宿主管理方式安全重启，再重新加载页面。确认插件已停用或移除、标准权限档可选、普通会话可用。服务部署从服务进程树之外重启。不要以删除源码链接代替正式卸载。

### 9.2 识别两种残留情况

安装期间在宿主设置改过默认权限预设时，宿主会把当时的整张预设表写进用户配置。插件不自动清理用户 YAML。从未改默认预设的安装不产生这类用户层条目。

| 情况 | 表现与影响 | 处理 |
| --- | --- | --- |
| 用户层仍保留 `auto-approve` 条目 | 插件移除后“自动审批”仍显示、可选；实际等同普通“工作区内修改”，没有本插件审查 | 改选标准档；需要彻底清理时按下一节只删该条目 |
| 默认仍指 `auto-approve`，预设表却已没有该条目 | 权限行无法加载，设置中的“权限”行消失、目录不可用，日志出现 `unknown preset`；会话仍可创建 | 还原备份，或把同一配置中的 `defaultPreset` 改为存在的标准档，例如 `workspace-write` |

条目仍显示不等于插件仍在工作。也不要为去掉显示就先删条目，却留下失效的默认引用。

### 9.3 手工只清理插件条目及失败回退

编辑前停止宿主，或确认没有设置写入正在进行，并保留备份。设置写入会即时写磁盘，不能同时编辑。

1. 先确认默认已选标准档。若页面可用，从设置页页头“打开配置文件”找到实际用户配置；否则由管理员定位 `profiles/<配置名>/cordis.patch.yml`。
2. 在 `- id: permission` 行的 `config.presets` 中，只删除 `auto-approve:` 条目及其缩进子行。保留其他预设、默认选择和无关行。
3. 安全启动或重载，确认权限行、标准预设及会话可用。
4. 出错时先恢复备份；若确认为默认引用失效，可将 `defaultPreset` 改回当前存在的标准档。不要删除整份用户配置。

无法确定编辑范围、设置仍不可用或恢复失败时，保留备份和脱敏宿主日志，交维护者核对。不要连续尝试批量删除配置。

### 9.4 插件数据何时删除

卸载后，profile 中的插件配置及插件数据默认保留，重装可继续读取已有配置、会话模型选择和审查记录。权限表中的 `auto-approve` 条目按前两节单独处理。

停用或卸载默认保留 `$DSH_HOME/approve-for-me/`；未设置 `DSH_HOME` 时是 `~/.dsh/approve-for-me/`。若确需清除，先停止使用该目录的宿主并备份，再仅删除这个插件数据目录。审查记录和会话模型选择会一并丢失，不能从卸载操作恢复。
