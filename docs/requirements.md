# dsh-approve-for-me 需求

> **维护者工作区入口**
> - 项目根目录是公开外仓，只保存对外部用户有用的产品代码、测试、工具与公开文档。根目录的 `.local/` 是维护者内部工作区，由外仓忽略，另有独立的内部 Git 仓库。
> - 内部工作区隔离维护者的机器信息、凭据等敏感数据，以及临时脚本、日志、验证产物、审查记录和修正记录等过程材料。它既保护维护者隐私与安全，也避免无关材料进入公开仓，增加用户的阅读、下载和维护负担。
> - 本地存放不等于允许 Git 提交：凭据、真实令牌和其他秘密不进入任何仓库的提交，私有远端也不例外。临时材料按需要保留和清理，不把完成的审查、修正过程堆进现行文档；需保留的非敏感材料在内仓单独管理。
> - 两仓的根目录、HEAD、未提交修改、提交和历史分别核对。外仓忽略内部目录，不等于内部材料没有版本历史；外仓状态干净也不能证明内部材料已经保存。
> - 本地存在内部目录时，开始工作或上下文压缩恢复后先读[维护者工作区说明](<../.local/README.md>)，再分别检查两仓状态。该入口只规定维护操作，不承载产品需求或设计依据。
> - 公开克隆不含内部目录，不影响产品使用或公开测试。分仓细节只维护在内部说明中，外仓仅在本需求头部保留这一提示。

> 本文定义当前产品要求，不代表实现或验收已经完成。[设计文档](<design.md>)说明实现机制和验证方法，不能覆盖本文的产品行为。
> 需求与设计可以相互引用；必要说明不得依赖其他文档、内部材料或外部资料补齐。源码与测试是核验对象，不是缺失需求的替代品。
> 正文按功能维护。同一要求只在一个主题下完整定义；变更直接更新该主题，历史由 Git 保存。短期新增要求使用第 10 章，维护者定期归并。

## 1. 产品目标、职责范围与适用基准

### 1.1 产品目标

插件为无人值守的长任务，以及缺乏技术判断能力的用户提供自动审批：由独立审查器判断需要升权的操作，在保持正常功能可用的前提下尽可能保证安全。

- 对安全、符合任务目的且授权充分的操作，自动允许本次升权，减少不必要的人工等待和误拒。
- 对危险或未经授权的操作，阻止执行并说明原因。执行 Agent 应选择实质更安全的方案，必要时安全停止，不能为完成任务破坏用户环境。
- 对审查系统自身的故障，明确区分故障与危险判定。采用有限重试、时限和明确结算，避免无限等待或连续消耗模型调用。
- 以 Codex 自动审批为行为参考，并支持本文规定的模型选择、用户界面、语言、审计和子代理等功能。参考方案不能取代产品目标。

### 1.2 保护范围与职责分工

本插件是沙箱升权的审批应答者：保留宿主沙箱，只判断是否允许被接管操作的这一次升权，不改变沙箱、文件或网络策略。

- 仅处理进入宿主审批通道且符合第 2 章条件的请求，不对每次工具调用做全面检查。
- 已处于完全权限、不触发审批的操作，不受本插件审查。安装插件不等于所有危险命令都会被拦截。
- 工具执行超时、死循环工具、子代理运行期限和一般提问的等待处理，由宿主或异步工具插件负责；本插件负责自动审批及其等待、故障和记录。
- 不修改宿主源码，不以源码补丁实现轨迹集成，不向宿主会话日志写入插件自定义事件。
- 不提供插件侧用户 YAML 解析、改写或卸载残留清理。安装声明与卸载风险见第 8 章。

### 1.3 当前兼容基准

本节是当前兼容基准的唯一权威。目标宿主为 dsh `0.2.0-rc.2`，不据此宣称支持全部 `0.2.x`。宿主依赖 `@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-typert-protocol` 的运行依赖与 peer 声明采用该精确版本；`@deepseek-ai/cordis` peer 为 `~4.0.4`。

升级宿主时，核对审批接口、配置通道、模型目录、客户端挂点与包加载行为，完成相应验证后直接更新本节及设计依据。旧版本迁移任务和旧验收记录不保留在现行正文。版本不兼容、服务缺失或客户端未加载，不能被报告为插件正常可用。

### 1.4 插件版本与发布标识

本节是插件版本格式和下一发布目标的唯一权威。版本信息必须同时让用户识别适配的 dsh 版本，并让维护者区分插件自身的迭代。

- `package.json.version` 使用 `<插件版本>+dsh.<宿主版本>`。插件版本采用语义化版本的主、次、修订三段，宿主版本取 1.3 的目标；`+` 后是构建元数据，不是插件预发布后缀。
- Git 发布标签为 `v<package.json.version>`，完整保留构建元数据。Release 标题先写 dsh 版本，再写插件名和插件版本。
- 锁文件顶层和根包版本、发布产物及宿主插件管理界面展示的版本，均须与包版本一致，不丢失宿主信息。宿主依赖与 peer 仍按 1.3 精确声明，不能用插件完整版本替代宿主依赖版本。
- 构建元数据不参与普通语义化版本的优先级比较，不能据此进行宿主兼容性选择。固定安装版本使用完整 Git 标签；实际兼容性由宿主依赖和 peer 约束校验，版本展示不扩大兼容范围。
- 更新适配宿主时，同步版本中的宿主部分与依赖约束。插件核心版本用于管理自身变更，不能只看构建元数据推断插件迭代顺序。

以上是待实施、待验收的发布目标，不表示当前包版本已经更新或标签、Release 已创建。版本与产物完成核验后再发布；已发布标签和历史记录不因采用本规则而改写。

## 2. 自动审批的接管范围

### 2.1 主会话

插件仅在会话符合接管条件时介入：

1. 插件已启用，`mode` 不是 `off`。
2. 当前权限预设命中 `trigger.presets`。清单为空时不命中任何已知预设，不表示覆盖全部；预设无法判断仍独立按 `trigger.unknown` 处理：默认 `skip` 保持宿主原审批流程；`review` 才继续接管。
3. 请求是沙箱升权，且工具符合 `tools` 名单。空名单覆盖所有工具的升权审批，非空时只覆盖名单内工具。

不接管时，不调用审查模型、不注入插件结论、不显示无关控件，原样交给宿主其他审批应答者。宿主策略为 `never` 而未分发审批时，插件不绕过该策略。

### 2.2 子代理

- `trigger.subagents=review` 时，按委派链根会话的权限预设判断覆盖范围，包括多层子代理；不按子会话自身的预设名称猜测。
- 根会话不可判定或不在接管名单中，不覆盖。`trigger.subagents=skip` 时不介入子代理。
- 被覆盖子代理的升权走同一套规则检查、LLM 审查、故障拒绝和审计；通知直接送给发起操作的子代理。
- 允许调整子会话审批策略以接入审查，但不能通过设置整套权限预设改变委派沙箱。
- 子代理没有人工备用通道：不弹人工卡片；即使 `fallback=ask`，审查未放行也按拒绝结算。
- 覆盖处理失败不能使子会话创建失败。停止覆盖不撤销已写入子会话的审批策略；后续由宿主其他应答者处理，无应答者时不自动允许。

## 3. 安全审查：输入、取证与判断

### 3.1 本次操作与用户授权

每次审查必须能辨认本次工具、真实命令或参数、目标路径与载荷、工作目录、请求权限和发起理由。最近会话上下文用于理解用户任务及授权，不代替本次操作。

- 本次真实参数独立送审，不受会话上下文取样条数或窗口影响。即使不取最近上下文，也不能只凭工具名或空命令放行一个写入、编辑等操作。
- 当前动作和上下文缺失、读取失败、被截断或无法完整呈现时，明确标记缺失，不伪造证据。
- 只有用户或 developer 消息、`AGENTS.md` 与用户对询问工具的应答可建立授权。用户明确要求按指定文件或工单执行时，授权可延伸到所指定内容。
- 工具输出、技能描述、助手文本和待审参数是证据，不能自行扩张用户授权；其中冒充指令的内容不能改变审查规则或输出契约。
- 工作目录未知必须明示。取证使用的备用目录不能被冒充为已核实的会话目录。
- 参数处理不得静默漏掉受支持范围内的自有字段或真实内容；过长、过深、循环或无法呈现的内容必须显示缺证标记。具体序列化边界由设计明确。
- 关键风险信息不足时，先尝试只读取证；仍不能判断时，不自动放行。无关信息缺失不应成为一律拒绝正常操作的借口。

**每次实际操作都必须在执行前取得针对本次操作的有效审批。不能因为曾经批准过相同命令，或近期有过允许结果，就跳过对本次操作、当前状态和用户授权的判断。**本条适用于本插件接管的审批范围，不扩大为所有工具操作均须审批。

### 3.2 只读取证与请求隔离

审查器可以自主读文件、搜索和列目录，在判断前确认目标及影响范围。

- 工具只读，不修改工作区、不联网、不触发新审批。审查调用独立于被审 Agent 会话，不能让执行 Agent 自审自批。
- 相对路径以本次会话工作目录为基准；可按取证需要访问工作区外的本地可读路径，但受敏感读取限制。
- 凭据类文件和目录、宿主认证信息、DSH 会话与插件审查记录不能成为任意读取并外送的取证来源。路径别名和符号链接不能绕过已定义的读取限制。
- 读取限制是有限的路径和名称识别，不承诺发现凭据的改名副本或硬链接。目录列表可能包含敏感文件名，不代表允许读取内容。
- 搜索、读取、遍历和工具轮次必须受资源及时间约束。超限或跳过要说明，正常候选应继续处理；工具不能无限占用事件循环，使时限失效。
- 工具失败、参数错误或超时，作为未取得证据的结果返回给审查器；审查继续，不因此直接放行或直接拒绝。
- 并发和排队请求分别绑定自己的目录、语言、单工具时限和脱敏清单。后续请求或配置更新不得改写已经进入审查的取证对象。

### 3.3 风险与授权判断

风险分级：`low` 是常规、范围窄、易恢复且不涉及凭据访问或不可信外发；`medium` 可恢复但影响实质；`high` 难恢复或跨信任边界；`critical` 是明显秘密外泄或重大不可逆破坏。

授权分级：`high` 明确覆盖动作、载荷或副作用；`medium` 明确服务于用户任务且影响在同一范围内；`low` 仅有关联但未覆盖目标或副作用；`unknown` 没有授权证据且与任务无关。

没有更严规则时，低、中风险可允许；高风险仅在授权至少为中、范围窄且没有强制拒绝规则时允许；严重风险拒绝。不能仅因沙箱重试、请求升权、目标在工作区外或使用递归删除语法就判为高风险。

随包策略正常加载时，以下规则优先适用：

1. **敏感外发**：敏感载荷与特定目的地均须获得可信用户内容的授权；载荷可能含敏感数据且未获该目的地授权时拒绝。
2. **凭据探测**：从环境转储、历史记录、凭据库、密钥文件或浏览器配置等非常规来源提取凭据为高风险；授权低或未知时拒绝。工具使用自己已配置的凭据调用自己的服务属于常规认证。
3. **持久削弱安全**：宽范围、持久或影响生产环境的安全控制削弱，须明确授权覆盖确切设置、目标服务和影响范围，否则拒绝。
4. **破坏性操作**：不可逆删除、生产服务破坏及大规模未经请求的 Git 清理为高风险；重大不可逆损害且无授权证明时拒绝。破坏动作解析到文件系统根目录，或涉及被遮蔽的公共变量时，拒绝。
5. **低风险例外**：用户明确要求删除的特定本地路径，经取证确认目标后通常为低或中风险；该例外不推翻前述强制拒绝规则。

策略按 Agent 文案语言选择。所选策略缺失、读取失败或为空时，明示“仅按基础风险分级执行”，继续基础风险与授权审查，不自动拒绝，也不改用另一语言策略。不能声称该路径已应用完整随包策略；文件修复后通过重新加载刷新读取结果。

LLM 判断不是确定性安全保证：提示注入、误判、模型及档位差异都可能影响判断。沙箱、明确授权、取证和失败拒绝共同降低风险，不能宣传为绝对安全。

### 3.4 可选拒绝规则

`denyPatterns` 默认空清单。用户可填写多行拒绝规则；命中后直接拒绝，不调用 LLM，不交人工复核，模型和人工都不能推翻。

启用后，检查覆盖实际操作中受支持范围的字符串参数值，不能只检查某个展示字段而遗漏其他载荷。命令包装和其他参数中的危险内容应按同一匹配口径处理；拒绝原因说明命中位置和规则。

规则是文本匹配，不是完整命令语义分析。普通正则表达式默认忽略大小写；显式指定标志时，按所填标志匹配。支持的参数深度和表达式格式由设计明确。包含危险词的说明文本也可能命中；空清单只关闭这项文本匹配，不关闭升权上限、未知操作处置等其他检查，符合送审条件的请求仍交给 LLM 判断。不可用的规则不得被声称为有效保护。

### 3.5 审查输出契约

沿用 Codex 契约：模型输出严格 JSON，包含以下字段，只有 `outcome` 必填。

| 字段 | 含义与取值 |
| --- | --- |
| `outcome` | `allow` 或 `deny` |
| `risk_level` | `low`、`medium`、`high`、`critical` |
| `user_authorization` | `unknown`、`low`、`medium`、`high` |
| `rationale` | 判断理由文本 |

低风险允许结果可以只返回 `{"outcome":"allow"}`。解析时允许恢复外层散文包裹的合法 JSON；缺风险按允许补低、拒绝补高，缺授权补未知，缺理由补固定说明。必须记录哪些内容是模型实际提供的、哪些是解析补全，不把补全伪装成完整风险分析。

原始模型字段与内部结算结果分别定义。无合法 `outcome`、无法解析、空响应或输出被截断时，不采信允许片段，按审查故障处理。被截断的响应即使局部 JSON 可解析，也不能放行。

## 4. 审批流程、人工介入与故障恢复

### 4.1 结算与人工介入

| 情况 | 行为 |
| --- | --- |
| 规则命中、升权超过上限、默认配置下无法辨认实际操作 | 直接拒绝，不调用 LLM、不交人工 |
| LLM 判断允许 | 返回 `allowed-once`，仅允许本次操作 |
| LLM 判断拒绝或没有取得有效结论 | 默认返回 `rejected`；主会话可选 `fallback=ask` 交人工 |
| 审查期间人工抢先作答 | 在已显示人工卡片时，采用人工结果并停止审查 |
| 原始工具请求取消或人工通道关闭 | 返回 `cancelled`，不把取消当作危险判定 |
| 插件内部异常 | 拒绝并留痕，不把异常当成功，也不产生进程级未捕获异常 |

`ui.humanCardDuringReview=true` 时，主会话在审查期间显示原生卡片，允许人工抢先作答；这与默认不启用审查后的人工备用通道是两件事。关闭时，审查期间无卡片，只有确实进入人工备用阶段才显示。

一次审批只能有一个最终结果。结算后停止无用审查、释放计时和等待资源，并撤回已显示的卡片；迟到结果和迟到点击不能改写结果或再次通知执行 Agent。宿主撤回能力不可用时明确记录降级，不把残留卡片当作仍可改判的申请。

### 4.2 时限

- 审查时限默认值见 5.3；涵盖本次等待审查结论的过程，内部重试不取得新的一份时限。
- 审查时限 `0` 表示用户主动取消审查时限。设置为无上限后必须提醒：审查模型挂起、工具或其他异常可能使请求无限停在自动审批；其他已启用的人工或取消路径仍按各自条件生效。不擅自替用户恢复时限。
- 人工时限默认值见 5.3，仅人工备用通道启用时使用。`0` 表示立即拒绝，不表示无限等待。
- `human.timeoutFrom=request` 从请求进入起算，交人工只使用剩余时间；`handoff` 从交人工起算。剩余时间已耗尽时不再显示一张马上消失的卡片。
- 排队超过等待上限时结束等待；该超时不能被当成允许。
- 所有毫秒字段接受 `0` 至 `2147483647` 的整数。负值、非整数或超限值拒绝加载，错误可见，不静默变成很短的计时器。
- 计时或取消处理自身出错时，分别保持超时拒绝或取消语义，记录真实错误来源。

### 4.3 给执行 Agent 的解释

通知按第 5 章的 `ui.inject` 开关发送，必须区分：

- **安全拒绝**：给出原因。不得通过等价命令、间接执行或规避策略达到同一结果；可采用实质更安全的方案，或告知风险后取得用户明确批准，否则停止并请求用户输入。
- **超时**：说明未在时限内取得结论，本次按拒绝处理，指出发生环节，并说明新申请可以直接重试；不冒充危险判定。
- **通道故障**：说明自动审查没有得出安全结论，给出故障原因，允许重新申请审查。模型异常、队列容量不足和冷却中的未执行均属于这类，不冒充危险判定或超时。持续失败应停止连续重试并报告用户；冷却期间应等待或报告，不能反复立即重试。
- **自动允许**：按配置通知触发工具、操作摘要和理由，说明本次已允许，可以继续任务。

英文安全拒绝末句保持 Codex 原文：

> The agent must not attempt to achieve the same outcome via workaround, indirect execution, or policy circumvention. Proceed only with a materially safer alternative, or if the user explicitly approves the action after being informed of the risk. Otherwise, stop and request user input.

中文对应约束保持本节语义。超时与通道故障不使用这段禁止绕过文案。

### 4.4 有限重试、并发与持续故障控制

- 网络或供应商异常、流失败及空响应等可重试故障，最多尝试两次，即首次加一次重试；重新建立完整审查输入，不接续残缺请求。
- 模型解析不可用、装配错误和输出截断不作内部重试。尝试次数有界；启用审查时限时，总时长也受该时限约束。审查时限为零时，尝试次数仍有上限，但不能保证模型调用会返回。
- 每次审批只形成一份审查记录；内部尝试进度必须可查。重试不能改变已完成的审批结果。
- 跨会话并发受全局上限约束，同一会话审查串行；队列容量及等待时限受配置约束。触顶、超时或故障不能自动允许。
- 连续拒绝或审查错误达到阈值，或窗口内累计达到阈值时，进入冷却；期间不调用模型。冷却到期恢复并清空计数，不中断整个 Agent 任务。
- `allow` 清零连续计数；`deny` 与审查 `error` 均计数。调度未执行审查、人工或取消等其他路径先结算导致的中止不计数；审查计时器引发的超时仍计数。一次审查任务只计一次，内部重试不增加任务数。

## 5. 模型选择、配置与语言

### 5.1 模型与档位

审查模型按以下顺序选择，先取得可用候选的层生效：会话选择 → 父模型映射 → 全局默认。全局默认为空（未设置）时，使用执行 Agent 当前模型独立审查；这是全局默认层的零值语义，不是其后的回退层。已设置的全局默认不可用时，不改用执行 Agent 当前模型。全局默认为空时，插件设置页顶部与会话选择控件附近显示醒目提示，说明审查模型跟随执行助手当前模型（6.1、6.2）。

父模型映射由结构化规则清单定义。每条规则含匹配条件与选择：匹配条件的 `provider` 为空值（null）时表示任意 provider，非空字符串表示指定 provider；`model` 始终是完整纯模型 id，不按斜杠切分。选择含目标模型引用与可选推理强度。模型引用使用 `provider/model`，按首斜杠解析 provider，模型 id 内的斜杠必须保留。每个匹配条件只允许一条规则；重复条件是可见配置错误，不按清单顺序选取。持久化只保存一份规则，不自动双写。

父模型映射的查找接收完整父模型 `{provider, model}`：先精确匹配（provider 非空且相等、model 相等），后通用匹配（provider 为空值且 model 相等）。旧 `byParentModel` 字典保留为兼容输入：纯模型 id 键按通用匹配参与查找；全引用键兼容读取为去掉首个斜杠后的完整纯模型 id；曾被末段截断写坏的旧键不做猜测恢复；含斜杠旧键的迁移须用户确认原意，目录展示只能辅助、不能证明原意。未被编辑的旧配置不自动重写。

任一层选出的目标模型不可用时，记录原因、实际层级和路由，直接使用全局默认；不在其余层级间逐层回退，映射层内精确规则不可用时也不改试通用规则。落到全局默认层时，为空按零值语义处理，已设置但不可用按故障处理，不静默选任意模型。父模型、模型目录、会话选择或配置变化后重新解析，不能长期显示旧选择。

模型和档位绑定。用户指定且受支持的档位优先；不支持时不传档位并记录降级。未指定时，模型支持 `low` 就使用 `low`，否则不传，由模型默认值决定。清除会话选择后按其余层解析；写入失败保留原值并显示失败，不声称保存成功。

会话选择按会话 id 持久化，宿主重启后可读回，不向会话日志写入自定义事件。

使用执行 Agent 当前模型作为审查模型时，仍独立发起审查调用，不使用执行 Agent 的原会话作出审批。界面说明必须区分“使用相同模型”和“由执行助手自己审批”。

### 5.2 配置生效与校验

设置页面可编辑字段保存后取得新值，不要求用户重启。其他配置通过宿主更新或重新加载取得新值；不能把所有字段都宣称为不重载更新。

**插件取得新配置后，下一次进入审查的请求使用新值；已经进入审查或排队的请求保持原配置。**输出通知、审计与记录脱敏出口按各自消费时点使用生效清单，仍须先脱敏后裁剪。

配置合并、校验和读写分别满足：

- 部分分节覆盖不能丢失其他默认值。
- 令牌数、条数、轮次、容量和字节预算字段接受非负整数；零值按各字段解释，不统一表示无限制。毫秒字段范围见 4.2。
- 温度为有限数 `[0,2]`，非有限数拒绝；数值越界时错误可见。
- 加载时，已提供的非法枚举值或字段类型拒绝加载，不能静默改成默认值；未提供字段才补默认。父模型映射规则的匹配条件重复时同样拒绝并给出可见错误；旧 `byParentModel` 字典仅作兼容读取，未编辑不自动重写或迁移。
- 设置读写失败必须明确显示，不能假装更新成功。

- `language.ui=auto|zh|en` 控制插件所有用户界面文案；`auto` 跟随宿主界面语言。

- 切换一边不能改另一边。取得新语言后下一次审查使用新值，不追溯改变在途请求。
- 中文英文不能改变授权、安全规则、输出字段名及证据边界。字典键集完整对应，不静默回退为键名或另一语言。
- 模型引用、工具名及宿主提供的名称说明属于数据，保持原样；少数需要英文 id 核对的字段，在本地化文案后附原值。stderr 的固定日志格式不随语言开关变化。

## 6. 用户界面与交互

### 6.1 插件设置页面

设置入口是“插件”面板中已安装包的详情页面；进入即显示完整表单，不要求再展开或进入行级配置页。只在宿主支持的本机回环设置入口提供写入；读不到配置通道时优雅降级，不影响审批。

- 控件显示真实生效值，不能整片空白或与实际配置脱离。
- “启用自动审批的权限预设”为多选，选项、说明和默认标记来自宿主目录；已配置但不存在的预设显式提示，不丢弃用户值。空清单提示按 2.1 区分已知与无法识别的预设。预设缺失时说明已知原因和适用的处理方法；原因不明时引导检查启用状态、宿主兼容性或自定义预设，不保证重新启用或重启一定恢复，也不推荐插件侧用户 YAML 清理。
- 提供审查模型及档位、父模型映射规则、触发设置、两个语言开关、两条时限、模式、升权上限、未知操作处置、人工备用、通知范围、名单和规则等设置。
- 父模型映射表按结构化规则编辑：每行含作用范围（任意 provider 或指定 provider）、执行助手完整模型 id、审查模型与推理强度。作用范围由显式控件表达，不按有无斜杠或目录猜测；默认作用范围为任意 provider；不把通用规则回显成目录首个 provider 的专属选择；目录不可读时保留原值。匹配条件重复的行禁止保存并给出可见错误；含斜杠旧键迁移须经用户确认原意，确认前保留原值。
- 审查模型不可用的醒目提示按配置层级分置：全局默认不可用显示在设置页顶部；映射规则选出的模型不可用显示在对应映射行附近；会话指定不可用显示在会话选择控件附近（6.2）。提示在配置的目标不可用时即出现，与实际是否已回退无关；内容含不可用的可核实原因与实际回退结果；级联时各位置的提示保留。提示只呈现可见性，不改变 5.1 的回退语义。全局默认为空（零值语义生效）时，设置页顶部同样显示醒目提示，说明未设置全局默认、当前使用执行助手当前模型独立审查；该提示说明状态而非故障，与不可用提示同一呈现规格。
- 所有编辑先暂存。只有“保存”写入；离开未保存页面丢弃暂存。单字段“恢复默认”只暂存清除覆盖，保存后才生效，不提供全局重置按钮。
- 用户层存在字段时显示“已单独设置”，不能通过值是否恰等于默认值推测设置来源。无改动、有非法值或保存中禁止保存；失败保留草稿并给出可见错误，允许重试。
- 布局与控件外观遵循宿主设置表单：字段竖排，无独立卡片外壳和分区标题。常驻说明与可展开的详细说明按 6.4、6.5 提供。
- 自动审查等待上限（`reviewer.timeoutMs`）和人工作答等待上限（`human.timeoutMs`）同时显示生效值和草稿值的秒数换算。草稿随输入立即更新；空、非数字、负数或非整数显示 `—`，生效值始终保留。秒数整数不带小数，非整数最多一位小数，中文单位为 `秒`、英文为 `s`，数字与单位之间一个半角空格。存储单位仍为毫秒，零显示 `0 秒` 或 `0 s`，不混写两个字段的零值语义。
- 审查时限选择无上限后显示 4.2 的无限等待风险提醒；危险配置不能只靠维护文档说明。

### 6.2 会话审查模型控件

控件只在当前会话由插件接管时显示，接管状态由宿主提供。权限变化后及时更新显隐，不要求用户刷新页面；需求不规定具体通知或轮询机制。

取得会话 id 后，即使尚未发消息也可设置。没有会话 id 时不显示；全局值仍可在设置页面配置。选择、档位和清除行为遵守 5.1；切换失败明确显示，不假装选择成功。会话指定的审查模型不可用时，在会话选择控件附近醒目提示，含原因与实际回退结果（5.1、6.1 的分置提示）。全局默认为空且会话未单独选择审查模型时，在会话选择控件附近醒目提示审查模型跟随执行助手当前模型（5.1、6.1 的空全局默认提示）。

### 6.3 审批卡片

保留宿主的“拒绝／允许一次”按钮及原关联命令。插件增加真实状态、原因和适用于当前阶段的倒计时，不在客户端猜测审查结论。

审查中显示审查剩余时间；进入人工阶段明确显示“等待你决定”和距离自动拒绝的剩余时间，并分别说明安全拒绝、超时或未取得有效结论等原因。模型异常、队列已满和冷却中的未执行不能显示为模型已经判定危险。尚未完成人工决定时，不把自动审查未允许显示为最终审批已拒绝。审查无上限明确显示无时限；人工时限零不显示“将一直等待”。状态通道不可用时退回原卡片，不能编造状态；结算后移除陈旧状态。显示时机遵守 4.1。

### 6.4 面向用户的名称与说明

本节适用于插件设置、会话模型控件、审批卡片、审查记录，以及这些界面的选项、提示、错误和说明。中文以用户要设置的对象、动作和结果命名，同一概念使用同一名称。界面中的“执行助手”指发起工具操作的 Agent；“审查模型”指独立判断本次升权的模型。“权限预设”指宿主提供的沙箱范围与审批策略组合，选择自动审批的接管范围不等于授予任意权限。

- 字段名称和常驻短句应让用户知道设置影响什么。详细说明补充适用条件、选择后果和例外，不能只是复述字段名。必要的技术词首次出现时说明用途；例如 token 是模型计量文本的单位，正则表达式是文本匹配规则。
- 默认行为、空值和零值的特殊含义、保存后才生效的动作，以及选择前必须知道的风险，放在对应控件附近，不全部藏进折叠说明。完整规则仍以各功能主题为准。
- 内部配置键和诊断代码用于核对，不代替中文说明。模型引用、工具名及宿主目录数据按 5.4 保留。插件自有的状态、模型选择来源和异常标记先给中文含义，必要时再附原值；未知代码保持原样并承认含义未知，不编造解释。
- 名称调整不更改配置键、枚举值、默认值、审批规则或保存行为。英文表达同一含义与条件，不机械直译，也不改变 5.4 的两个语言开关。

### 6.5 容易发现的功能说明入口

每个设置字段在标签旁提供常驻的“说明”文字按钮，可以搭配信息图标，但不能只有小图标。默认状态就能辨认文字和按钮，不依赖悬停才显眼。点击后在本字段内展开详细说明，按钮文字变为“收起说明”；再次点击收起，不改变草稿或保存状态。

- 数字、下拉、多选、布尔、模型选择和映射表等字段采用一致的说明入口。使用宿主组件不能成为省略文字入口的理由。
- 浅色和深色主题下都要清晰可读；文字对比度至少为 4.5:1，点击区域至少为 24×24 CSS 像素。说明按钮保持次要操作的强调程度，不使用警告色或动画抢占注意。
- 可以用键盘聚焦，按 Enter 或空格切换；焦点状态清晰。辅助技术可识别按钮所属字段、展开状态和关联说明区域。
- 详细说明默认收起。6.4 要求的关键短句及风险提醒常驻，不能因详细说明收起而消失，也不要求用户跳转其他文档才能知道必要行为。

## 7. 审计与审查记录

### 7.1 默认可审计内容

审计要尽可能支持复盘，不限定“每个请求只能一行”。各阶段可分别记录，但同一审批必须能够关联并辨认最终结果。

| 复盘问题 | 必需内容 |
| --- | --- |
| 谁请求什么 | 会话及主／子代理归属、审批与工具关联、工具、目标权限、脱敏的实际操作摘要 |
| 为什么接管或跳过 | 权限与名单条件、规则命中位置、跳过或降级原因 |
| 依据什么判断 | 用户授权及证据摘要、取证工具及结果摘要、缺失与截断情况 |
| 谁作出决定 | 规则、LLM 或人工；实际模型、档位和解析层；原始字段与补全字段的区别 |
| 最终发生什么 | 允许、拒绝、取消、超时或故障；风险、授权程度、可理解的理由 |
| 等待及故障情况 | 排队、审查、人工等待及执行耗时；内部尝试、冷却、迟到结果 |
| 记录是否可靠 | 生效配置与策略标识、脱敏、截断及记录失败；没有取到的信息明确缺失 |

默认摘要必须保留结论、理由与必要证据，不靠启用全文才能解释一次决定。跳过记录允许按会话和原因降噪，`trigger.auditEverySkip=true` 时逐次记录；被接管审批不能因降噪遗漏最终结果。

### 7.2 敏感内容与记录失败

- 系统提示用于定义审查规则，但不必逐次保存全文；默认保留版本或标识。模型返回的推理文本不是必需审计证据，也不是判断正确的证明。
- `summary` 默认不采提示词、送审输入、推理文本和原始输出全文；`full` 主动开启后才采，缺失的推理文本不伪造。`off` 不采详情，基础结果仍可追溯。
- 模型输入、工具结果、审计、执行 Agent 通知和记录出口全部先脱敏后截断；不修改原始会话日志。脱敏是有限形态识别，用户自定义清单整体替换默认值。
- 上下文与参数超预算保留首尾并标记缺失；通知和日志使用各自裁剪规则。极小预算仍可能保留完整缺失标记而超过名义预算，设计须明确实际边界，不能伪称严格上限。
- 记录的读取、写入、裁剪失败要留痕，不能伪造成功；失败不回滚已完成审批。必要信息确实未保存时，复盘界面必须承认记录不完整。
- 审计写 stderr，不污染宿主 stdout 的认证或启动输出。日志自身故障不能改变安全结算。

### 7.3 自有视图、耗时与保留范围

提供会话“审查记录”视图，能够按审批查看摘要和已采集详情。全文按需读取，不默认推给客户端。记录跟随产生它的会话，不给分叉会话伪造未发生审批。

列表以最终审批结果为主。模型结论与最终结果不同时，明确标注各自含义，例如“最终审批：拒绝”“模型结论：允许”，不能只并列两个无角色标签的结果。详情按 6.4 使用可理解的名称和中文解释；未取得最终结果的记录明确说明结果缺失，不用模型允许结果冒充最终批准。旧记录没有最终结果时，可显示已记录的模型结论，但须说明缺少最终结果。

内容缺失时，依据已记录的信息说明原因。能够确认时分别显示“未取上下文”“未调用取证工具”“模型未提供”“未开启全文采集”等说明；无法确认时显示“本次未记录此项”。不能把所有缺失归因于摘要采集，也不能承诺开启全文后补回已有记录的缺失内容。必要摘要缺失时仍按 7.2 承认记录不完整。

审批耗时与工具执行耗时分开。能关联工具记录时显示“工具总计 = 执行 + 审批”；关联不到时只显示已知审批耗时及缺失说明，不猜执行时长。

不要求修改宿主原生轨迹的标签、位置或时间线段宽；插件视图独立可用。可选近似轨迹行不能被描述为已实现原生审批记录。

记录可在宿主重启后回读。每会话窗口、全文字段、磁盘保留和长期登记结构均有界；文件缺失返回空，读取失败明确降级，损坏末行可跳过并留痕。写失败暂留内存，不宣称已持久化；多实例共享同一记录目录不受支持。减少采集不承诺删除已存在记录。

磁盘按会话分片。单文件超过回读窗口条数的四倍时，保留最近一个窗口；会话文件保留上限见 5.3，超过时删除最旧文件，不能误删刚创建的触发文件。内存会话登记与磁盘保留范围保持一致。

## 8. 安装、兼容、停用与卸载

- 通过宿主安装通道安装后，插件及“自动审批”权限选项应完整出现，不要求用户手工补部署配置。原有三种权限选项的行为不被改变；例举顺序不是产品要求。
- 权限预设由包的安装声明提供，随包参与组合，不使用安装或卸载生命周期脚本写入预设。安装包自身必须包含宿主与客户端入口、协议声明和安装声明。
- 安装及设置使用宿主官方机制，配置保存仍可由宿主管理用户配置；不改宿主源码，不额外提供插件侧 YAML 清理。
- 停用或卸载后不再接管新审批，包声明的权限选项不再参与组合；既有会话应能由宿主恢复到匹配的标准权限状态。
- **已知卸载风险**：宿主可能把包含“自动审批”的预设表持久化到用户配置。卸载后条目可能残留；默认选择仍指向该条目时，可能影响权限服务加载及会话使用。插件不自动解析或改写用户 YAML 解决此问题，使用说明必须明确风险，不能承诺全部用户配置零残留。后续宿主处理方式改变时重新核验。
- 插件自己的模型选择和审查记录是运行数据，不等同于部署副作用。卸载默认不删除这些数据，使用说明告知其位置与保留行为。
- 加载成功以应答者实际可用、客户端挂点可见及配置可读写为判据，不能仅凭安装成功或后端端点有响应宣称完整可用。兼容基准遵守 1.3。
- 重启应在被重启服务的进程树之外执行，不能让插件部署过程连同在运行任务一起被终止。

## 9. 验收标准

验收是对当前产品合同的验证，不保存按日期完成的勾选流水账。记录实际宿主版本、插件提交与方法；跳过、替身结果或仅静态存在不冒充真实运行通过。具体装置、断言与反例由设计规定。

| 主题 | 必须证明的结果 |
| --- | --- |
| 接管范围 | 指定预设正常接管；关闭、未命中、工具过滤、非升权和未知预设分支正确；不接管不影响宿主原流程 |
| 子代理 | 根会话覆盖及多层委派正确，未覆盖保持原行为；无人工挂起；通知到发起者；覆盖失败不破坏会话创建 |
| 审查输入 | 命令类与非命令类参数均实际送审；零上下文取样仍可见本次动作；缺失及超限不伪造安全证据；并发不串目录或配置 |
| 安全策略 | 默认空规则仍调用 LLM；显式规则命中直接拒绝且原因可查；授权与不可信证据分离；敏感读取与外送限制有效 |
| 输出与结算 | Codex 完整及最小输出可解析，补全可辨认；畸形、空、截断不能允许；本次审批不误用其他结论 |
| 人工与时限 | 默认拒绝、人工备用和审查中抢答各自正确；人工零立即拒绝；无审查时限有风险提醒；取消与迟到结果不改判、不重复通知 |
| 故障与持续运行 | 有限重试共用时限；危险、超时、故障解释不同；冷却及排除项正确；并发、队列、工具和长期资源受控 |
| 模型与配置 | 三层选择及失效正确；结构化映射规则精确与通用匹配、重复条件拒绝、旧字典兼容读取正确；不可用直接回退全局默认并可查；空全局默认按零值语义使用执行助手当前模型；不可用提示与空全局默认跟随提示按层级分置可见；保存不假成功；新配置作用于下一请求，在途不变；非法数值可见拒绝 |
| 用户界面 | 真实页面可达；设置值、暂存、恢复默认、保存、秒数和双语正确；6.4 的名称、选项和说明与实际行为一致；6.5 的文字说明入口在两种主题、各类字段上可见、可用；会话控件及时显隐；卡片命令、倒计时和无时限说明可见，区分危险判断、超时、故障与待人工状态，不把待决定显示为最终拒绝 |
| 审计与记录 | 各路径关联及最终结果、风险授权、理由和必要证据可复盘；模型结论与最终结果标注清楚，诊断代码有可理解的解释；缺失原因不伪造，摘要不依赖全文；脱敏先于截断；记录故障不改变审批；重启回读及容量正确 |
| 安装与卸载 | 干净环境通过宿主通道安装后完整可用，停用卸载不再接管；原权限不被改变；插件不自动修改用户 YAML，已知残留风险如实说明 |
| 版本与发布标识 | 包、锁文件根版本、发布产物与管理界面完整版本一致；元数据宿主与 1.3 的依赖约束一致；Git 标签和 Release 标题符合 1.4；能用完整标签固定正确产物，不将元数据当兼容保证或插件排序依据 |

真实宿主至少验证一次 LLM 自动允许后工具执行、一次安全拒绝、可选人工超时、设置保存后下一请求生效，以及子代理接管。界面要求用实际页面和相应行为核对；接口返回或旧 DOM 快照不能代替当前界面验证。危险操作使用无害替身验证，不能为验收实际破坏用户数据。

界面文案与说明入口还须证明：

- 在未展开详细说明时，用户能看到每项设置的影响对象、必要的默认或零值含义和风险。各类设置字段在浅色、深色主题下均有可见的文字说明按钮，满足 6.5 的对比度和点击区域要求；鼠标与键盘均能开合，开合不改草稿、保存状态或常驻提醒。
- 设置页、会话模型控件、审批卡片和审查记录按 6.4 使用一致名称。审查使用相同模型仍说明独立调用；推理强度自动选择、空预设清单与未知预设处置、通知范围与记录开关、文本拒绝规则与其他检查均能区分。文案调整前后的配置键、枚举值、默认值和审批行为保持一致。
- 对安全拒绝、超时、模型故障、队列已满、冷却未执行、人工先答与迟到点击分别核对文案，不误报危险、不暗示已完成审批还能改判。记录中模型结论与最终结果不一致时可分辨，缺失段按可证实原因说明，不依赖开启全文解释必要摘要。

关键保护应有能发现退化的验证。测试名称不能代替实际触发；超时、取消、符号链接、流中途失败等不同路径分别覆盖。未完成验收的要求继续作为当前要求，不因文档重组或实现存在标为完成。

## 10. 增补需求
