# dsh-approve-for-me

[![CI](https://github.com/MC5Spear/dsh-approve-for-me/actions/workflows/ci.yml/badge.svg)](https://github.com/MC5Spear/dsh-approve-for-me/actions/workflows/ci.yml)

> 第三方社区插件，与 DeepSeek Harness 官方无关。个人维护，接受 issue，不接受外部 PR；响应与修复时间视维护者可用时间而定。安全问题同样通过 issue 提交，请先脱敏。

为无人值守长任务和需要协助判断操作风险的用户提供沙箱升权审查。独立的大语言模型（LLM）审查器可以读取本地证据，按操作风险和用户授权决定是否允许本次操作。危险拒绝与审查故障会分别说明。

**English summary.** This third-party DSH plugin reviews sandbox-escalation approval requests with an independent LLM and read-only local tools. An approval authorizes one operation. Built-in checks reject matched dangerous command patterns before model review; review failures are denied by default and reported separately from safety denials. LLM reviews can make mistakes, so keep the sandbox and back up important data. Before uninstalling, switch back to a standard permission preset; the host may retain plugin preset entries in user configuration. See [uninstall guidance](<#卸载与已知风险>) for preparation and recovery options.

## 先了解风险与保护范围

- 只审查进入插件接管范围的沙箱升权请求。“完全权限”下不触发审批的操作不受保护。
- 允许仅对本次操作有效；再次执行时需要本次有效审批。
- LLM 可能误判或受提示注入影响。请保留沙箱，重要数据先备份，再按任务需要收窄接管工具、权限预设和升权上限。操作参数、文件内容和工具结果本身不构成你的授权。
- 内置危险命令拦截在接管范围内始终启用。`denyPatterns` 默认 `[]`，只表示未启用自定义文本拒绝规则；两者的区别及拒绝后的处理方法见[内置危险命令拦截](<#内置危险命令拦截>)。
- 审查失败、超时、输出不可解析或模型不可用时，默认拒绝。可按[审批结果](<#审批结果与只读取证>)区分原因并处理。
- 默认不启用审查后的人工备用通道，可通过 `fallback=ask` 开启。主会话默认在审查期间显示人工卡片，可抢先作答；委派子代理没有人工通道，分叉会话按主会话处理。
- 建议先在非生产环境试用。使用自定义拒绝规则时，先用无害样本检查匹配范围，避免误拒正常操作。
- 停用或卸载后，宿主用户配置中可能仍有插件预设。默认选择失效可能影响会话，操作前请按[卸载说明](<#卸载与已知风险>)做好准备。

## 兼容性

安装前，按[当前兼容基准](<docs/requirements.md#13-当前兼容基准>)选择匹配的宿主与插件版本。插件版本中的宿主信息及完整 Git 标签格式见[插件版本与发布标识](<docs/requirements.md#14-插件版本与发布标识>)。

若宿主日志出现 `skipping profile bundle "dsh-approve-for-me"`，先核对版本要求，并改用匹配的版本。宿主升级后，确认“自动审批”预设和插件设置仍可见，再用无害操作检查审批及记录；功能缺失或行为异常时，按[常见问题与反馈](<#常见问题与反馈>)处理。

## 安装

### 宿主通道

宿主安装通道需要 pnpm。可运行 `corepack pnpm --version` 检查是否可用；命令失败时，先为宿主安装环境准备 pnpm，再安装插件。

```powershell
dsh plugin --profile web add github:MC5Spear/dsh-approve-for-me
```

也可在宿主“插件”安装对话框填写同一包地址。安装后，插件会提供“自动审批”权限预设。固定包版本时使用完整 Git 标签，包括版本中的宿主信息；普通语义化版本范围不按构建元数据选择兼容宿主。

重启会中断宿主中的运行任务，请先等待任务结束或安全停止。服务方式部署时，从服务进程树之外的管理终端重启，避免连同重启命令一起终止。重启后重新加载页面，检查“自动审批”选项与插件设置表单。

### 本地克隆与链接

将最后一行的占位符替换为克隆目录的绝对路径，保留引号以处理含空格的路径。链接模式从克隆目录解析依赖，请先完成依赖安装，再添加插件。

```powershell
git clone https://github.com/MC5Spear/dsh-approve-for-me.git
cd dsh-approve-for-me
npm install --omit=dev
dsh plugin --profile web add "<克隆目录的绝对路径>"
```

添加后，按前述步骤等待任务结束、重启宿主并检查页面。

## 配置与使用

1. 打开“插件”面板 →“已安装”→ 本包，编辑包详情页中的设置并保存。
2. 在要启用自动审批的会话中，选择“自动审批”权限预设。安装插件不会自动将它设为默认。
3. 默认接管“自动审批”预设的升权请求。若需覆盖其他预设，在插件设置中调整“启用自动审批的权限预设”。

设置页面写入需要通过宿主本机的回环地址访问，例如 `127.0.0.1` 或 `localhost`。远程页面不可写时，可改用本机入口，或由部署管理员通过宿主的 profile 配置管理设置；审批仍按已生效配置运行。

通过 profile 配置时，使用 `approve-for-me` 配置命名空间。默认值见[配置默认值](<docs/requirements.md#53-配置默认值>)。

| 设置 | 使用要点 |
| --- | --- |
| `enabled`、`mode`、`trigger.*` | 控制接管；空预设表不命中已知预设，未知预设仍按 `trigger.unknown`；委派子代理按根会话判断 |
| `trigger.auditEverySkip` | 开启后逐次记录因预设不匹配而跳过的审批 |
| `tools`、`allowEscalationTo` | 收窄工具和升权范围；空工具名单覆盖全部升权工具 |
| `denyPatterns`、`unknownSubject`、`fallback` | 自定义拒绝规则、缺操作证据和人工备用处置；规则空清单不影响内置危险命令拦截 |
| `reviewer.model`、`reviewer.parentModelRules` | 选择审查模型与推理强度；按执行助手模型命中的规则先于全局默认 |
| `reviewer.timeoutMs`、`human.timeoutMs`、`human.timeoutFrom` | 控制审查及人工等待；等待类零值一律立即到点（审查零立即超时、人工零立即拒绝），审查时限涵盖装配 |
| `reviewer.maxTokens`、`reviewer.temperature`、`reviewer.maxToolSteps`、`reviewer.toolTimeoutMs` | 控制模型响应和取证；工具轮次用尽要求直接回答；输出预算零不传上限，过小可能无有效结论；单工具零立即超时 |
| `context.*` | 控制上下文取样和脱敏；条数零不取上下文，本次真实参数仍独立送审；清单空表关闭遮蔽 |
| `concurrency.*`、`breaker.*` | 控制审查并发、排队及持续故障冷却 |
| `ui.inject`、`ui.injectMaxBytes`、`ui.humanCardDuringReview` | 通知范围、文本预算与审查期间人工卡片 |
| `ui.trace.*`、`audit.*` | 控制记录视图、保留范围和采集内容；敏感全文按需主动开启 |
| `language.ui`、`language.agent` | 界面文案与模型文案独立切换 |

合法类型和范围见[配置生效与校验](<docs/requirements.md#52-配置生效与校验>)及[时限](<docs/requirements.md#42-时限>)。草稿无效时，按字段提示修正后再保存；加载配置报错时，先修正配置再重载。

### 模型选择与配置更新

审查模型按“会话选择 → 按执行助手的模型映射 → 全局默认”的顺序选择。你可以在会话控件中指定本会话的审查模型；清除会话选择后，使用映射或全局默认。

会话或映射选出的模型不可用时，直接回退全局默认。使用全局默认时，留空表示使用执行助手的当前模型，独立于执行助手会话发起审查；已设置的全局默认不可用时，按故障拒绝。设置页和会话控件会提示不可用原因与实际回退结果，可据此修改模型选择。

模型引用格式为 `provider/model`，首个斜杠分隔供应商标识与模型 id，模型 id 内其余斜杠保留。推理强度与模型绑定：未指定时，支持 `low` 就使用 `low`，否则由模型默认值决定；指定的强度不受支持时，不向模型传该参数，并记录降级。

`reviewer.parentModelRules` 是结构化规则表，每条规则含作用范围与执行助手模型（完整纯模型 id，不切斜杠）：

- 作用范围＝任意 provider：任意 provider 下模型 id 相同即命中；
- 作用范围＝指定 provider：仅该 provider 下的该模型 id 命中。

同一作用范围与执行助手模型只能有一条规则，重复的行不能保存。旧 `reviewer.byParentModel` 字典继续参与匹配：纯模型 id 键按「任意 provider」读取；含斜杠的键在设置页请求确认原意，确认前按兼容规则读取、原值保留，不自动改写。

会话控件按当前会话的预设接管范围显示，权限变化后自动更新。取得会话 id 后，在发第一条消息之前也能设置；切换失败时保留原值，按错误提示处理后可重试。

设置页面中的编辑先暂存，只有“保存”才写入。“恢复默认”也需保存才生效；离开页面会丢弃未保存修改。“已单独设置”表示用户配置中存在该字段，即使值恰好等于默认值也会显示。毫秒字段同时显示生效值与草稿值的秒数，保存单位仍为毫秒。

设置页面可编辑字段保存后无需重启；其他配置按宿主的更新或重载方式生效。新配置用于后续请求，在审查或排队中的请求继续使用原配置与取证目录。脱敏规则更新后，随后发送的通知和保存的记录使用更新后的规则。

**审查时限设为零**：立即超时并按超时拒绝（不开始尝试）；需要较长等待时设较大的值。人工零同样立即到点（立即拒绝）。

### 内置危险命令拦截

在插件接管的升权请求中，以下命令形态会在模型审查前直接拒绝。该层不能通过配置关闭，人工也不能推翻；清空 `denyPatterns` 不会关闭它。

| 常见命中形态 | 处理方法 |
| --- | --- |
| PowerShell `Remove-Item` 及其别名带 `-Recurse`；POSIX `rm` 同时带递归与强制标志；CMD `del /f`、`erase /f`、`rd /s /q`、`rmdir /s /q` | 核对目标与备份后，改用不命中拦截的更安全方案，如移入回收位置，再重新申请审查 |
| 带强制或递归标志的删除，目标使用变量、命令替换或其他运行时求值，无法从命令文本确定；或未给出目标 | 确认实际路径，将目标明确写入新的申请；若仍含上一行的命中形态，需一并调整操作方式 |
| `mshta` 或 `rundll32 url.dll,FileProtocolHandler` 加 http／https 地址 | 改为由用户核实并打开网址，或先获取内容、完成审查后再处理 |

拦截按命令文本匹配，也会误拒命令中的引用或说明，例如提交信息、搜索词中出现上述形态。发生误拒时，查看拒绝原因中的命中位置；仅移除说明中的命中字样，或改用实质更安全的操作后，可重新送审。不要只换等价写法达到同一危险结果。

其中 `rm -r` 会按 PowerShell 的 `-Recurse` 缩写匹配，在 POSIX 命令或 `git rm -r` 中也会直接拒绝。详细匹配范围见[硬性危险拦截层](<docs/design.md#121-硬性危险拦截层需求增补-h1h2h3>)。

### 可选拒绝规则

`denyPatterns` 每行填写一条正则表达式，即文本匹配规则。默认空清单；填写后，命中会直接拒绝，并在原因中说明参数位置与规则。模型和人工都不能推翻命中结果。

规则检查受支持深度内的全部字符串参数值，包括命令包装、其他载荷和说明文本。普通表达式默认忽略大小写；`/source/flags` 格式使用所填标志，未填标志时同样忽略大小写。无法编译的行会跳过，请先用无害样本检查规则是否有效、是否误伤。

以下是可选参考清单的节选，需自行添加到配置才生效。完整清单见[设计 3.5](<docs/design.md#35-可选拒绝规则>)：

```text
(^|[^A-Za-z0-9])(mkfs|diskpart|fdisk|parted)\b
(^|[^A-Za-z0-9])format\s+[a-z]:
```

这些词出现在说明文本中也可能命中，换一种命令写法也可能漏匹配。请结合模型审查和沙箱使用，不依赖文本规则判断全部操作风险。

## 审批结果与只读取证

| 结果或原因 | 含义与下一步 |
| --- | --- |
| 安全允许 | 只授权本次操作，执行助手可继续任务 |
| 内置拦截或自定义文本规则命中 | 未进入模型审查。查看命中位置，按规则说明改用更安全的方案后重新申请 |
| 升权超过上限 | 使用较小权限的方案；确需更宽权限时，由用户核对风险后调整 `allowEscalationTo`，再重新申请 |
| 安全拒绝 | 查看理由，采用实质更安全的方案；需要原操作时，先告知风险并取得用户明确授权，再重新申请。内置拦截和文本规则命中仍会直接拒绝，不可用等价手段规避 |
| 超时 | 装配、排队、审查或人工等待未在时限内完成，默认拒绝；启用人工备用且该路径可交人工时，可转入“等待你决定”，由人工作答或人工超时结束审批。装配包括读取配置、选择审查模型和取得本次操作参数。可按原因检查时限，必要时发起新申请 |
| 通道故障 | 未得出安全结论。检查模型可用性或错误提示；有限重试后仍失败时，停止连续请求并反馈。冷却期间先等待，不立即反复重试 |
| 取消或人工作答 | 取消终止本次审批；人工作答采用该人工结果，插件不额外发送模型结论 |

主会话的原生卡片保留命令及“拒绝／允许一次”按钮，增加自动审批状态和当前阶段倒计时。进入人工阶段时显示“等待你决定”；超时或模型故障不表示模型已判定危险。状态服务不可读时显示宿主原卡片。

取证工具为 read_file、list_dir、glob、grep，只读、不联网、不触发审批。读取／搜索有大小、候选和时间限制；凭据类路径、DSH 会话、认证及审查记录受限。允许必要的工作区外本地取证，但不允许 UNC 或设备命名空间读取。名称限制不识别改名副本和硬链接；目录列表可能包含敏感文件名而不允许读内容。

## 审计与轨迹集成

在会话的“审查记录”中查看每次审批的结果、理由及已采集详情。默认 `summary` 保存摘要；需要记录后续审查的提示词、送审输入、模型返回的推理文本和原始输出时，可主动开启 `full`。记录先脱敏后裁剪，但有限的脱敏规则可能漏掉敏感内容，开启全文前请确认保存位置的访问权限。开启全文不能补回已有记录的缺失内容。

- 列表以“最终审批”结果为主。模型结论与最终结果方向不同时分别标注；旧记录缺少最终结果时，会显示“未记录最终审批结果”。
- 详情中的决定方式、理由和缺失说明用于区分规则拒绝、模型判断、人工决定及故障。模型返回的推理文本只是一项可选记录，不能据此认定判断正确。
- 关联到工具记录时，可查看“工具总计 = 执行 + 审批”。审批耗时分为排队、审查、人工等待，缺失段显示“—”。
- 页面提示“记录读取失败或不完整”时，不能据此判断没有发生审批。请保留现有记录并按[反馈步骤](<#常见问题与反馈>)报告，避免先删除文件。

宿主标准错误日志（stderr）也记录操作、接管原因、模型、结果、耗时及故障。同一次审批可能对应多条日志，排障时应保留可关联的相关行。

重启后会回读每会话最近的记录窗口。较早记录会因窗口、文件轮转或会话文件数量上限退出可见范围或被删除；需长期留存时，应在轮转前另行安全备份。窗口与容量值见[配置默认值](<docs/requirements.md#53-配置默认值>)。记录写入失败时可能只留在内存，重启后会丢失；收到写入故障后，应先保留现有日志并反馈。多个宿主实例请使用各自的数据目录。

## 卸载与已知风险

宿主设置页修改默认权限预设时，会把当时的预设表整表写入用户配置（`profiles/<配置名>/cordis.patch.yml`）。插件安装期间改过默认预设的，停用或卸载后该文件仍保留「自动审批」条目；插件不会自动清理用户配置。从未修改默认预设的安装不产生该用户层条目。

残留条目本身不影响权限服务加载：预设列表里仍显示「自动审批」、仍可被选为默认，但插件已不在，选择它的行为等同普通「工作区内修改」。仅当默认选择仍指向「自动审批」而预设表已不含该条目时（例如手工删除了表内条目、或宿主更新改变了预设表），权限行才会加载失败：设置页的「权限」行消失、预设目录不可用，宿主日志出现 `unknown preset`，会话仍可创建。

停用或卸载前：

1. 等待运行任务结束或安全停止。
2. 将宿主数据目录中 `profiles/<配置名>/` 下的用户配置备份到安全位置；需要留存的审查记录也先备份。
3. 将宿主默认权限预设和需要继续使用的会话切回标准档，通常选择“工作区内修改”——这一步让默认引用指向有效条目，是彻底清理的前置条件。

卸载命令：

```powershell
dsh plugin --profile web remove dsh-approve-for-me
```

重启宿主并重新加载页面后，检查插件已移除、标准权限档可选且会话可用。

彻底移除残留条目需要手工编辑用户配置：经设置页页头的“打开配置文件”入口（或自行编辑 `profiles/<配置名>/cordis.patch.yml`），在 `- id: permission` 行的 `presets` 块中只删除 `auto-approve:` 条目及其子行，其余内容不动；编辑前停止宿主或确认没有正在进行的设置写入（设置写入即时落盘），并保留备份。删除条目前默认预设必须已是标准档，否则会出现上文“权限行加载失败”形态；该形态的恢复是按备份还原文件，或在该文件中把 `defaultPreset` 改回标准档。设置不可用、编辑后仍异常或会话无法使用时，保留配置备份和宿主日志，按[反馈步骤](<#常见问题与反馈>)交给维护者核对恢复方法。不要在未确认影响范围时删除整份用户配置。

会话模型选择与审查记录保存在 `$DSH_HOME/approve-for-me/`；未设置 `DSH_HOME` 时为 `~/.dsh/approve-for-me/`。卸载默认保留这些数据。需要清除时，先停止使用该目录的宿主并完成备份，再仅删除该插件数据目录；其中的记录和模型选择会一并丢失。

## 常见问题与反馈

| 现象 | 先检查什么 | 后续处理 |
| --- | --- | --- |
| 找不到“自动审批”或插件设置 | 插件是否已启用、宿主版本是否匹配、重启及页面重载是否完成 | 任务结束后再重启；仍缺失时提供版本及加载错误 |
| 设置页面不可写或保存失败 | 是否通过本机回环地址访问、字段是否有校验错误 | 改用本机入口或请部署管理员配置；保存失败时先保留草稿内容，再处理错误并重试 |
| 操作直接被拒绝 | 拒绝理由是内置拦截、自定义规则、升权上限，还是模型判断 | 按[审批结果](<#审批结果与只读取证>)选择处理办法；内置拦截不能靠清空自定义规则关闭 |
| 持续超时或模型故障 | 审查模型是否可用、时限是否为零、是否处于冷却期 | 修正配置或等待冷却；仍失败时停止连续请求并反馈 |
| 记录缺失或不完整 | 页面缺失说明、全文采集是否开启、日志是否有写入错误 | 保存现有证据后反馈；开启全文只影响后续记录 |

需要帮助时，按[报 issue 的要求](<CONTRIBUTING.md#报-issue>)提交最小可复现信息：宿主与插件版本、触发步骤、脱敏配置、相关审计行或截图。提交前去掉凭据、私人路径和会话内容；不要用真实危险操作复现问题。维护者据此核对原因和处理办法。

需要在克隆仓库中运行测试或模型探针时，参阅[环境准备与测试说明](<CONTRIBUTING.md#环境准备fork--复现用>)。
