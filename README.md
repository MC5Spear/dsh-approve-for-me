# dsh-approve-for-me

[English](<README.en.md>) · 中文

执行助手申请更宽的沙箱权限时，这个插件审查能否允许本次操作。它安装在 DeepSeek Harness（DSH）中。DSH 是运行执行助手的应用。

独立的大语言模型负责审查操作和用户授权。审查模型可以用只读工具核对本地证据。

这是第三方社区插件，与 DeepSeek 官方无隶属关系。

## 安装

当前适配线尚未发布。请向维护者取得实际交付的 `.tgz` 安装件，或对应的完整源码目录。安装前核对完整版本、适配宿主和交付标识。

安装前，先完成两件事：

1. 若已有本插件，先关闭接管，并把默认权限预设和活动会话切回标准档，例如“工作区内修改”。
2. 等待宿主中的任务结束，或安全停止。安装后的重启会中断运行任务；服务部署须从服务进程树之外的管理终端重启。

宿主安装通道需要 pnpm。用 `corepack pnpm --version` 检查；不可用时，先请部署管理员为该宿主准备 pnpm。

把下面的占位符替换为**维护者交付的真实文件绝对路径**，保留引号：

```powershell
dsh plugin --profile web add "<安装件的绝对路径.tgz>"
```

源码目录的依赖准备、安装和更新方法见[安装参考](<docs/user-reference.md#installation>)。安装后安全重启宿主，再重新加载页面。

### 首次确认

1. 在“插件”→“已安装”中打开 `dsh-approve-for-me`，核对完整版本。
2. 确认详情页有设置表单；立即将“模式”设为“完全不接管”并保存。
3. 确认会话权限列表有“自动审批”（`auto-approve`），但当前仍选择标准权限档。这是本插件的预设，不要与宿主 id 为 `auto` 的选项混淆。
4. 确认普通会话可用。设置或预设缺席时，按[排障步骤](<docs/user-reference.md#troubleshooting>)处理，不要放宽版本要求强行加载。

安装成功不等于自动审批已经可安全使用。当前应保持关闭，直到维护者交付并确认修复版本。

## 启用前要知道什么

以下说明也适用于之后的修复版本：

- 只审查进入接管范围的升权请求。“完全权限”下不触发审批的操作不受保护。
- 每次允许只对本次操作有效。相同命令再次执行，仍需本次有效审批。
- 模型可能误判，也可能受提示注入影响。保留沙箱，备份重要数据，再按任务收窄接管工具、权限预设和升权上限。
- 操作参数、文件内容和工具结果是证据，本身不能代表你已授权。请明确说明目标及允许的副作用。
- 内置危险命令拦截始终随接管生效。清空自定义 `denyPatterns` 不会关闭它。审查超时、模型不可用或没有有效结论时默认拒绝；拒绝后的处理见[结果与重新申请](<docs/user-reference.md#results>)。
- 只读核对可能把本地内容送给配置的模型供应商。脱敏只能识别有限文本形态；开启全文记录前还要检查存储目录权限。

## 配置与使用

**当前版本先保存 `mode=off`。以下启用流程留给维护者确认修复后的版本使用。**

1. 在插件详情页选择审查模型、接管工具和权限上限，保存设置。
2. 将模式改为“规则检查 + LLM 审查”并保存。
3. 在需要自动审批的会话中选择“自动审批”（`auto-approve`）权限预设。安装不会自动把它设为默认。
4. 先用无害、确需升权的操作试用。查看会话“审查记录”，核对最终结果、理由和实际模型；不要用危险操作验证拦截。

设置写入需要宿主本机回环入口，如 `127.0.0.1` 或 `localhost`。保存失败时草稿保留；离开页面则丢弃未保存内容。单字段“恢复默认”也要保存。详细方法见[设置与恢复](<docs/user-reference.md#settings>)。

主会话默认在审查期间显示人工卡片，你可以抢先作答。这与审查结束后的人工备用通道不同：后者默认关闭，需设 `fallback=ask`。委派子代理没有人工通道；用户分叉会话按主会话处理。

## 停用与卸载前

先关闭接管，再把宿主默认权限预设和需要继续使用的会话切回标准档。备份配置及所需记录后，再停用或卸载。

宿主可能保留“自动审批”的用户配置条目。条目残留不表示插件仍在工作；错误删除条目却保留默认引用，可能让权限设置无法加载。完整步骤及失败恢复见[停用、卸载与恢复](<docs/user-reference.md#uninstall>)。
